 Lecture 8 (LIVE): Understanding Algorithm
 Properties and Linear Data Structures
 Overview
 This lecture covered two main topics: the essential properties that algorithms must possess and an
 introduction to linear data structures, specifically arrays and linked lists. The session emphasized
 how algorithms should be designed with specific characteristics to ensure they work effectively in
 real-world applications, while data structures provide organized ways to store and manage data
 efficiently.

 Algorithm Properties
 Technical Properties
 Finiteness
 • An algorithm must terminate after a countable, finite number of steps
 • It should not loop indefinitely
 • Example: Counting students in a class will eventually end, whereas continuously waiting for new
    customers entering a store without a time limit would be infinite
 Definiteness
 • All steps must be clear and unambiguous with no confusion
 • Instructions should be precise enough to be understood by anyone following them
 • Example: "Calculate average by adding five numbers and dividing by five" is definite, whereas
    vague instructions like "add some tea powder" in a tea-making process are ambiguous
 Well-Defined Input
 • Input requirements must be clearly specified
 • Example: For calculating rectangle area, you must specify that length and width are needed, not
    just "required values"
 Well-Defined Output
 • The expected output must be clearly stated
 • Example: A loan approval algorithm should specify "Approved" or "Rejected," not just "Processing
    complete"
 Effectiveness
 • Every step must be basic enough to execute in finite time using simple operations
 • Example: Inventory management algorithm stating "if stock is less than 50 units, order 200 units"
    is effective, whereas "check stock and order if needed" without specifying threshold is vague

 Execution and Design Properties
 Language Independence
 • Algorithms should not depend on any specific programming language
 • They should be expressed in plain English or pseudocode understandable to anyone
 • Implementation choice (C, Python, Java) comes later
 Determinism
 • Same input must always produce the same output

 • Example: Loan approval (based on quantitative criteria) is deterministic, whereas visa application
    (involving subjective interviews) is not
 Feasibility
 • An algorithm must operate realistically within available system memory and processing power
 • Must be implementable with available resources (money, time, space)
 • Example: Processing all employee payroll sequentially is feasible; attempting parallel processing
    of simple calculations is infeasible
 Generality
 • Algorithm should handle all possible situations, not just specific cases
 • Example: Don't hardcode employee names or fixed number of subjects; make it flexible to accept
    any number of subjects or employees

 Algorithm Approaches
 Divide and Conquer
 • Break large problems into smaller subproblems, solve them separately, then combine results
 • Example: Regional sales analysis (dividing by regions, analyzing each, then combining for total)
 Greedy Algorithm
 • Make locally optimal choices to find a quick solution within available resources
 • May not be globally optimal but works well for practical purposes
 • Example: Cashier returning change using largest denominations first
 Dynamic Programming
 • Consider past solutions and decisions when making current decisions
 • Example: Production companies planning based on seasonal trends from previous quarters

 Linear Data Structures
 Arrays
 Characteristics
 • Elements stored in sequential locations with specific indexes
 • Fixed size must be defined during creation
 • Same data type for all elements
 • Indexes typically start from 0
 • Can be single or multi-dimensional
 Basic Operations
 • Read/Access: Retrieve values from specific index (fast if index known)
 • Search: Find specific items within array (sequential search if index unknown)
 • Insert: Add new elements (easiest at end, more complex in middle as items must shift)
 • Update: Modify existing values (fast if index known)
 • Delete: Remove content at index (only clears data, doesn't free memory)
 Benefits
 • Simple to understand and implement
 • Quick access if index is known
 • Memory efficient for known fixed-size data
 • Ideal for predictable data sets
 Limitations
 • Fixed length; resizing is resource-intensive

 • Requires contiguous memory locations
 • Insertion and deletion in middle can be time-consuming
 • Not suitable for frequently changing data

 Linked Lists
 Characteristics
 • Items connected through memory references (links/pointers)
 • No fixed size; can grow dynamically
 • Each node contains data and reference to next node
 • Starts with a "head" pointer
 • Flexible arrangement of items
 Types
 • Singly Linked List: One-directional links (forward only)
 • Doubly Linked List: Two-directional links (forward and backward)
 • Circular Linked List: Last node points back to head for continuous cycling
 Basic Operations
 • Add: Insert anywhere by rearranging memory references
 • Remove: Delete by updating linkages
 • Rearrange: Change order by modifying pointers
 • Navigate: Move through items following links
 Benefits
 • Dynamic size; can add unlimited items
 • Flexible insertion and deletion at any position
 • No need for contiguous memory
 • Ideal for frequently changing data
 Limitations
 • More complex to understand and implement
 • Slower access compared to arrays (must follow links)
 • Additional memory required for storing references
 • Cannot randomly access items by index

 Comparison: Arrays vs. Linked Lists
 Arrays are preferred when data size is known and predictable, frequent access is needed, and
 simplicity is important. Linked lists are preferred when data size is unknown, frequent
 insertion/deletion occurs, and flexibility is required. A practical example: Music playlists benefit from
 linked lists because songs can be easily added, removed, or reordered without restructuring the
 entire collection.

 Foundation Importance
 Both arrays and linked lists serve as foundational data structures. Other data structures such as
 stacks, queues, trees, and graphs are typically implemented using either arrays or linked lists,
 making understanding these basics essential for computer science applications.

 Lecture 9: Stacks: A Linear Data Structure with
 Last-In-First-Out Operations
 Overview
 Stacks are linear data structures that follow the Last-In-First-Out (LIFO) principle, where the most
 recently added element is the first one to be removed. This lecture covers the fundamental
 concepts, operations, and practical applications of stacks, including their implementation
 approaches and common errors.

 Real-World Applications and Examples
 Undo Functionality in Word Processors
 • When using applications like Microsoft Word, the undo feature relies on stack operations
 • Each change made to a document is stored in a stack
 • Clicking undo removes changes in reverse chronological order (last change first)
 • This behavior directly corresponds to stack's LIFO nature
 Physical Stack Examples
 • Stack of plates at a buffet or wedding
 • Stack of newspapers
 • Weighing plates in a gymnasium
 • In all cases, items are added and removed from the top only

 Stack as a Data Structure
 Basic Definition
 • A stack is a data structure where new elements are always stored at the top of the list
 • Elements are retrieved (removed) only from the top
 • Logically organized memory spaces behave in a stack manner, though physical memory locations
    may not be hierarchical
 Key Principle
 • Whatever element was put in last remains at the top and is removed first
 • This is why stacks are called LIFO (Last In First Out) data structures

 Core Stack Operations
 1. Push Operation
 • Adds a new element to the top of the stack
 • Requires specifying the value to be pushed
 • Example: push(64) adds 64 to the stack top
 2. Pop Operation
 • Removes and returns the top element from the stack
 • Does not require specifying a value (removes whatever is on top)
 • Example: pop() removes the current top element
 3. Peak Operation
 • Examines the top element without removing it

 • Useful for checking what's available before deciding whether to pop
 • Example: peak() returns the value at the top
 4. Size Operation
 • Returns the total number of elements currently in the stack
 • Useful for memory management and constraint checking
 • Example: size() returns the count of elements

 Types of Stacks
 Static Stacks
 • Fixed in size and predefined during creation
 • Cannot grow beyond the specified limit
 • Typically implemented using arrays
 • Examples:
     – Adobe Photoshop: Default limit of 50 undo operations
     – Microsoft Excel: Default limit of 100 undo operations
 • Settings can be customized based on available memory and system capability
 Dynamic Stacks
 • Variable in size and grow as needed
 • More flexible than static stacks
 • Typically implemented using linked lists
 • Example: Microsoft Word uses dynamic stacks for undo operations
 • Can grow until memory limitations are reached
 • Practically limited by available RAM and system resources

 Stack Errors
 Stack Overflow
 • Occurs when attempting to push an element into a full stack
 • Can happen with both static stacks (by definition) and dynamic stacks (due to memory
    limitations)
 • Results from exceeding allocated memory or capacity
 • Common error in programming (noted by the popularity of Stack Overflow website)
 • Real-world example: Opening too many browser tabs causes memory overflow
 Stack Underflow
 • Occurs when attempting to pop an element from an empty stack
 • Happens when more pop operations are performed than available elements
 • Results in a null or undefined error
 • Real-world example: Clicking the browser back button when no previous pages exist

 Implementation Approaches
 Static Stack Implementation
 • Uses arrays as the underlying data structure
 • Array size must be predefined
 • Suitable when maximum capacity is known and limited
 • More efficient for fixed-size requirements
 Dynamic Stack Implementation
 • Uses linked lists as the underlying data structure


LECTURE 9 (Recorded)                                                                      Page 6
 • Allows for flexible growth and shrinkage
 • Suitable when size requirements are variable
 • Better for applications with unpredictable storage needs

 Advanced Concepts
 Stack of Stacks
 • Concept of nested stacks where each element in a stack is itself a stack
 • Real-world example: Multiple browser windows, where each window contains multiple tabs
 • Each tab history could be represented as a stack within the main stack
 Memory Considerations
 • Static stacks: Stack is cleared when file is saved (in applications like Excel and Photoshop)
 • Dynamic stacks: Limited by physical memory (RAM) of the device
 • System crashes may occur if memory is exhausted
 • Frequently saving files helps manage stack size in applications

 Key Takeaways
 • LIFO Principle: Stacks operate on the last-in-first-out principle, making them ideal for undo
    operations and backtracking
 • Four Main Operations: Push, pop, peak, and size cover all standard stack operations
 • Implementation Choice: Static stacks use arrays; dynamic stacks use linked lists
 • Error Management: Understanding overflow and underflow errors is crucial for proper stack
    implementation
 • Practical Applications: Stacks are fundamental to many real-world computing scenarios beyond
    just undo operations

 Lecture 10: Fundamentals of Queue (Q) Data
 Structure
 This lecture introduces Queue (Q), another essential linear data structure, following previous
 discussions on arrays, linked lists, and stacks. The session is divided into two parts: fundamentals
 and types/applications of queues.

 Overview and Real-World Concept
 A queue operates on the principle of First Come First Served (FCFS) or First In First Out (FIFO). Using
 the example of a movie theater popcorn counter, elements are processed in the order they
 arrive—whoever arrives first is served first, regardless of what they purchase. This principle mirrors
 real-life queue behavior.

 Queue Definition and Characteristics
 • Queue is a linear data structure where elements are arranged in order of arrival
 • First element stored remains at the front of the queue
 • Latest elements are added at the rear
 • Retrieval process starts from the front and moves toward the rear
 • Alternative terminology: While stacks are Last In First Out (LIFO), queues are FIFO structures

 Primary Queue Operations
 Enqueue (NQ)
 • Adds an element at the rear (end) of the queue
 • When the queue is empty, the first element occupies both front and rear positions
 • Front pointer remains stationary; rear pointer advances with each insertion
 Dequeue (DQ)
 • Removes and returns the element at the front of the queue
 • Front pointer moves forward to the next element
 • Rear pointer remains unchanged
 • Unlike the push and pop operations in stacks, dequeue requires no parameters
 Peek/Front Operation
 • Displays the value at the front of the queue
 • Does not remove the element
 • Returns the current front value without modifying the queue
 Rear/Back Operation
 • Displays the value at the rear of the queue
 • Does not remove the element
 • Indicates the most recently added element
 Size Operation
 • Returns the total number of elements currently in the queue

 Queue Errors
 Queue Overflow
 • Occurs when attempting to enqueue an element into a full queue
 • Specific to static queues with fixed capacity
 • Example: Multiple users attempting to book tickets on IRCTC simultaneously, overwhelming the
    server's request queue
 Queue Underflow
 • Occurs when attempting to dequeue from an empty queue
 • Happens when no elements are available for removal
 • Example: Streaming data buffer becomes empty due to internet disconnection, causing video
    playback to freeze

 Static vs. Dynamic Queues
 Static Queue
 • Fixed size determined at initialization
 • Typically implemented using arrays
 • Limited capacity, susceptible to overflow errors
 • Used in hardware-constrained environments
 Dynamic Queue
 • Variable size that expands as needed
 • Typically implemented using linked lists
 • Can grow to accommodate more elements
 • Better suited for applications with unpredictable data volumes

 Practical Applications
 Static Queue Applications
 • Wi-Fi Routers: Data packets are stored in fixed-size queues; network congestion causes queue
    overflow, leading to dropped packets using the "tail drop mechanism"
 • Keyboard and Mouse Buffers: Hardware buffers with fixed capacity; rapid inputs exceeding
    processing speed result in dropped keystrokes or mouse clicks
 • Vending Machines: Fixed hardware capacity; each drink type occupies a specific queue with
    predetermined storage limits
 Dynamic Queue Applications
 • Messaging Applications (WhatsApp): Local dynamic queues store typed messages when internet
    connectivity is lost; messages are transmitted sequentially once connection is restored,
    maintaining the order in which they were typed
 • Streaming Services (Netflix, Spotify, Amazon Prime): Segments are buffered in dynamic memory
    queues, allowing playback to continue even during temporary connection interruptions
 • Food Delivery Apps: Orders from thousands of customers require variable-capacity queues;
    dynamic implementation prevents order loss during peak demand periods

 Important Concepts to Remember
 • Queue elements maintain their order of arrival throughout processing
 • Front pointer location changes during dequeue operations, not during enqueue
 • Peek operation is crucial for examining queue state without modifying it
 • Queue implementation choice (static vs. dynamic) depends on whether data volume is
    predictable and whether overflow is acceptable
 • Real-world systems often fail gracefully when queues become full (dropped packets, ignored
    keystrokes) rather than crashing

 Lecture 11: Queue Types and Applications (Part
 2)
 Overview
 This lecture continues the discussion on queues by exploring four distinct types of queues: linear,
 circular, priority, and double-ended queues (deques). Each type addresses specific use cases and
 operational requirements, with applications ranging from real-world scenarios to computer system
 processes.

 Linear Queue
 • Basic Operation: Elements are inserted (enqueued) at the rear and removed (dequeued) from the
    front
 • Pointer Movement: The front pointer points to the first location where an element is stored, not
    necessarily the first memory location in an array
 • Primary Limitation: Memory wastage occurs when the rear pointer reaches the end of the array,
    even if space is available at the front due to deleted elements
 • Static Implementation Issue: In array-based implementations, once the rear pointer reaches the
    array's end, new elements cannot be inserted, regardless of available space created by dequeue
    operations

 Circular Queue
 • Key Feature: The last position connects back to the first position, creating a circular structure
 • Memory Efficiency: Reuses empty space created by dequeue operations, preventing wastage
    found in linear queues
 • Pointer Behavior: The rear pointer can continue moving into previously occupied spaces when
    elements are dequeued from the front
 • Implementation: Can theoretically be used indefinitely for insertion and deletion operations
 • Real-World Applications:
     – Traffic light systems (red → green → yellow → red)
     – Multiplayer games with sequential turns (players rotate back to the first player after the last)
     – Music playlists with looping enabled
     – CPU task scheduling using round-robin scheduling (multiple applications receive processing
       time in sequence)

 Priority Queue
 • Operational Principle: Elements are served based on priority level rather than insertion order
 • Priority Determination: Prioritization follows specific policies and is independent of when elements
    entered the queue
 • FIFO Exception: When elements have the same priority, standard FIFO order applies
 • Real-World Applications:
     – Hospital emergency rooms (triage system prioritizes accident cases over recurring
       headaches)
     – Airport traffic control (long-haul flights with limited fuel receive priority over short-haul flights)
     – Railway systems (express trains like Rajdhani and Shatabdi receive green signals priority)



LECTURE 11 (Recorded)                                                                                  Page 11
     – CPU task scheduling (system tasks receive higher priority than application tasks)
     – TATKAL ticket bookings (separate quota with priority access)
     – Disaster management (rescue operations prioritize individuals in immediate danger)

 Double-Ended Queue (Deque)
 • Flexibility: Elements can be added and removed from both the front and rear ends
 • Dual Functionality: Combines characteristics of both queues (FIFO) and stacks (LIFO)
 • Four Core Operations:
     – Insert front: Add element at the beginning
     – Insert rear: Add element at the end
     – Delete front: Remove element from the beginning
     – Delete rear: Remove element from the end
 • Real-World Applications:
     – Browser navigation (back and forward buttons allow movement through history in both
       directions)
     – Word processors (undo and redo functionality)
     – Train coach management (coaches can be added or removed from either end)
     – Doubly linked lists (often implement deque structures)

 Queue of Queues
 • Concept: A main queue containing elements that are themselves queues (sub-queues)
 • Streaming Application: OTT platforms like Netflix use this structure where:
     – Main queue holds upcoming scene segments of a video
     – Sub-queues contain individual video frames or packets within each segment
     – Videos are displayed as continuous motion through rapid sequential display of static images
 • Interruption Handling: When internet connection drops, the system preserves progress in the
    main queue but must restart from the beginning of the interrupted sub-queue, causing videos to
    restart slightly before the interruption point

 Key Takeaways
 • Linear Queue: Regular line following FIFO (First In First Out) principle
 • Circular Queue: Ring-shaped line that reuses empty spaces and prevents memory wastage
 • Priority Queue: VIP line where urgency determines service order
 • Deque: Open-ended line allowing entry and exit from both sides

 Lecture 12: Introduction to Nonlinear Data
 Structures: Trees
 This lecture introduces trees, the first nonlinear data structure, contrasting them with linear data
 structures like arrays, linked lists, stacks, and queues where paths are predetermined. Trees feature
 multiple possible paths through their elements, creating hierarchical relationships between nodes.

 Core Concepts and Terminology
 Fundamental Definition
 • A tree is a data structure where elements are arranged hierarchically rather than sequentially
 • Each unit or element in a tree is called a node
 • Nodes are connected by edges (lines linking parent to child nodes)
 Key Node Types
 • Root node: The first and topmost element of the tree (drawn at the top diagrammatically)
 • Child node: A node connected below another node
 • Parent node: A node that has one or more child nodes connected to it
 • Leaf node: Terminal nodes with no child nodes (found at the end of any pathway)
 Essential Tree Properties
 • A node can have multiple children, but each node can have only one parent
 • A tree cannot have a node with two parents (distinguishes trees from graphs)
 • The structure prevents circular connections

 Family Tree Use Case
 A practical example demonstrates tree structure using a family hierarchy:
 • Grandfather (root) has three children: Son A, Son B, and Daughter
 • Son A has one daughter (D1)
 • Daughter has two sons (S1 and S2)
 • Son B has no children
 This illustrates how trees effectively represent hierarchical relationships with clear parent-child
 dependencies.

 Tree Properties: Depth and Height
 Depth (represented as lowercase d)
 • Measures how far a node is from the root
 • Calculated by counting the number of edges needed to reach from the node to the root
 • Root node has depth = 0
 • Each subsequent level increases depth by 1
 • Every node has its own unique depth value
 Height (represented as lowercase h)
 • Represents the maximum depth value in an entire tree
 • Measures the distance from root to its deepest leaf node
 • A single value that characterizes the entire tree



LECTURE 12 (Recorded)                                                                                  Page 13
 • Calculated by finding the node requiring the most edges to reach from root

 Sub-trees
 • Any section of a tree that is a child of another node constitutes a sub-tree
 • A tree can be understood as multiple nested sub-trees
 • Similar to how a branch of a real tree resembles a complete tree when viewed independently

 Real-World Applications
 • Folder Structure: Computer file systems organize folders hierarchically where each subfolder
    belongs to only one parent folder
 • Corporate Hierarchy: Organizations structure employees with CEO at root, managers as
    intermediate nodes, and workers as leaf nodes
 • Book Classification: Libraries organize books through hierarchical systems—language → genre →
    subgenre → author → title
 • Biological Classification: Taxonomy arranges organisms hierarchically (animal → vertebrate →
    mammal → dog)
 • Family Trees: Represent genealogical relationships across generations (typically following
    patrilineal lines to maintain single-parent constraint)

 Tree Traversal Methods
 Tree traversal refers to the process of reading or visiting all nodes in a tree. The non-linearity of
 trees creates multiple valid traversal paths, unlike linear structures.

 Depth-First Traversal Methods
 Depth-first traversals follow the logic until reaching the deepest leaf nodes before backtracking. The
 position of the root node determines the traversal type.
 Pre-order Traversal (Root, Left, Right)
 • Root is visited first
 • Then traverses left subtree
 • Finally traverses right subtree
 • Example: A, B, D, E, C
 In-order Traversal (Left, Root, Right)
 • Left subtree is visited first
 • Then root node
 • Finally right subtree
 • Typically works clearly only when nodes have at most two children
 • Example: D, B, E, A, C
 Post-order Traversal (Left, Right, Root)
 • Left subtree is visited first
 • Then right subtree
 • Root node is visited last
 • Example: D, E, B, C, A
 Key Rule: In all traversals, left subtree always comes before right subtree

 Breadth-First Traversal (Level-Order)
 • Starts from root at top level
 • Proceeds to next level, then next, working downward
 • At each level, traversal moves left to right


LECTURE 12 (Recorded)                                                                                Page 14
 • Unlike depth-first methods, this stays at each level before descending
 • Example: A, B, C, D, E

 Traversal Characteristics
 • All traversals follow the principle that left branches are processed before right branches
 • Depth-first methods require careful attention to root position
 • Level-order traversal is visually intuitive but algorithmically requires different implementation
 • Traversal methods are essential for reading and processing tree data due to multiple valid paths

 Key Takeaways
 • Trees organize data hierarchically with single-parent constraint per node
 • Depth applies to individual nodes; height applies to entire tree
 • Multiple traversal methods exist due to non-linear structure
 • Each traversal method serves different algorithmic purposes
 • Trees are fundamental for representing hierarchical relationships in real-world applications
 • Future sessions will cover specialized tree types used in algorithms

 Lecture 13 (LIVE): Linear Data Structures: Stacks
 and Queues
 Overview of the Lecture
 This lecture continues the study of linear data structures, covering two fundamental types: stacks
 and queues. While arrays allow indexed access and linked lists use connections between elements,
 stacks and queues have unique operational characteristics that make them essential for specific use
 cases.

 Stacks (LIFO - Last In First Out)
 Definition and Concept
 A stack is a linear data structure where the most recently added element is the first one to be
 removed, following the LIFO (Last In First Out) principle. This differs from queues which follow FIFO
 principles.

 Real-World Examples
 • Wedding plates: Fresh plates are placed on top; the most recently placed plate is taken first
 • Document editing (Undo function): The last change made is the first one undone when using
    Ctrl+Z
 • Newspaper stacks: The latest newspaper sits on top
 • Browser history: Recent pages visited are accessed first

 Basic Stack Operations
 • Push: Adds a new element to the top of the stack
 • Pop: Removes and returns the top element from the stack
 • Peek: Views the top element without removing it
 • Size: Returns the number of elements currently in the stack

 Stack Implementation Approaches
 Static Stack
 • Fixed size determined at creation
 • Implemented using arrays
 • Memory-efficient for predictable sizes
 • Examples: Adobe Photoshop (50 undo operations), Microsoft Excel (100 undo operations)
 Dynamic Stack
 • Size can grow as needed
 • Implemented using linked lists
 • Provides flexibility but requires more memory management
 • Example: Microsoft Word (theoretically unlimited undo, limited by available RAM)

 Stack Errors
 Stack Overflow
 • Occurs when attempting to push an element onto a full static stack
 • Example: Opening too many browser tabs causes system memory stack to overflow


LECTURE 13 (LIVE LECTURE)                                                                          Page 16
 • System cannot allocate additional space for new elements
 Stack Underflow
 • Occurs when attempting to pop from an empty stack
 • Example: Clicking the back button in a browser with no history
 • No element exists to return

 Applications of Stacks
 • Undo/Redo functionality in applications
 • Function call management in programming
 • Expression evaluation and parsing
 • Depth-first search algorithms
 • Browser navigation history

 Queues (FIFO - First In First Out)
 Definition and Concept
 A queue is a linear data structure where the first element added is the first one to be removed,
 following the FIFO (First In First Out) principle. Elements are inserted at the rear end and removed
 from the front end.

 Real-World Examples
 • Movie ticket queues: People are served in the order they arrive
 • Network printer queues: Print jobs are processed in the order they are submitted
 • Restaurant service: Customers are served based on arrival order (when properly managed)

 Basic Queue Operations
 • Enqueue (NQ): Adds an element to the rear end of the queue
 • Dequeue (DQ): Removes and returns the front element
 • Peek (Front): Views the front element without removing it
 • Peek (Rear): Views the rear element
 • Size: Returns the number of elements in the queue

 Queue Types
 Linear Queue
 • Simple implementation with front and rear pointers
 • Memory wastage problem: When elements are dequeued, the front moves forward but empty
    cells cannot be reused
 • Implemented using arrays
 Circular Queue
 • Logically arranged in a circular manner (not in physical memory)
 • Solves the memory wastage problem of linear queues
 • When the rear pointer reaches the end, it wraps around to the beginning if space is available
 • Implemented using linked lists
 • Applications: Traffic lights, multiplayer games (turn-based), music playlists
 Double-Ended Queue (Deque)
 • Allows insertion and deletion from both ends
 • Combines properties of stacks and queues
 • Can add/remove from front or rear

 • Applications: Browser forward/back buttons, undo/redo functionality
 Priority Queue
 • Elements are served based on priority rather than strict FIFO order
 • Higher priority elements are served first
 • If priorities are equal, FIFO order is maintained
 • Applications: CPU task scheduling, hospital emergency rooms (triage), airline boarding

 Queue Errors
 Queue Overflow
 • Occurs when a static queue is full and a new element is attempted to be added
 • Example: Concert ticketing system becomes full during high-demand periods
 • Server may reject new requests, causing apparent system hang
 Queue Underflow
 • Occurs when attempting to dequeue from an empty queue
 • Example: Video streaming freezes when buffer queue becomes empty
 • Happens when internet connection is lost during streaming

 Queue Implementation Approaches
 Static Queue
 • Fixed size, implemented using arrays
 • Applications: Network printer buffers, keyboard buffers (16-64 bytes), Wi-Fi router packet queues
 Dynamic Queue
 • Variable size, implemented using linked lists
 • Applications: WhatsApp message queues, streaming services (Netflix, YouTube, Hotstar)

 Real-World Applications
 Network Printing
 • Print jobs queue at the printer in FIFO order
 • Printer has fixed memory to store pending jobs
 Streaming Services
 • Video is essentially a series of consecutive images played in sequence
 • Uses queue of frames at receiver end (client buffering)
 • Uses multiple queues (queue of queues) for different video segments
 • When connection is slow, buffering pauses and older frames are played
 CPU Task Scheduling
 • Round Robin scheduling: CPU allocates time slice to each task, then moves to next task
 • Shortest Job First: Tasks with shorter execution time get priority
 • Continuous task switching creates perception of parallel processing
 Keyboard and Mouse Input
 • Input buffer stores keystrokes in a queue
 • If typing speed exceeds processing speed, buffer can become full

 Lecture 14: Introduction to Non-Linear Data

 Overview
 This lecture continues the exploration of non-linear data structures, specifically focusing on different
 types of trees and their practical applications in computer science. The session builds upon
 fundamental tree concepts including hierarchical arrangement of elements, tree properties (depth
 and height), and traversal methods covered in the previous session.

 Recap of Tree Fundamentals
 • Tree Definition: A data structure where elements are arranged hierarchically, with each node
    capable of having multiple children, but each child having only one parent
 • Key Properties:
     – Depth: The distance of a node from the root (number of jumps required)
     – Height: The distance from a node to its deepest leaf
 • Traversal Methods: Depth-first traversals (3 types) and breadth-first traversal

 General Trees
 Definition: A tree where nodes can have any number of children with no fixed minimum or maximum
 constraints.
 Characteristics
 • No restriction on the number of children per node
 • Variable branching factor across different nodes
 Real-World Applications
 • Computer folder and directory structures
 • Family trees (patrilineal representation)
 • Organizational hierarchies with variable reporting structures
 • Biological taxonomy and classification systems

 Binary Trees
 Definition: A tree where each node can have at most two children (meaning zero, one, or two
 children are possible).
 Key Concept: "At most" means the maximum is fixed at two, but the minimum is not restricted.
 Characteristics
 • Maximum of two children per node
 • Nodes can have zero, one, or two children
 • Still classified as binary tree if some nodes have fewer than two children
 Real-World Applications
 • Tournament knockout structures (sports competitions where two teams compete, winners
    advance)
 • Decision trees and flowcharts with yes/no decision points
 • Binary decision processes in systems (ATM transactions, quality checks)

 Complete Binary Trees
 Definition: A binary tree where all levels except the last are completely filled with exactly two
 children per node, and the last level is filled from left to right.
 Key Rules
 • All levels before the last must have exactly two children per node
 • Last level can have fewer than two children
 • Last level must be filled left to right (no gaps)
 • If a node at the last level has one child, it must be the left child
 Structural Requirement: Ensures efficient storage and minimal wasted space in tree representation.

 Binary Search Trees (BST)
 Definition: A binary tree with an additional ordering property where values matter and must follow a
 specific arrangement pattern.
 Fundamental Property
 • Left subtree values are always less than the parent node value
 • Right subtree values are always greater than the parent node value
 • This property holds recursively for all subtrees
 Value Location Patterns
 • Minimum value: Found by traversing left continuously from root until reaching a leaf
 • Maximum value: Found by traversing right continuously from root until reaching a leaf
 Applications
 • Dictionary searches in traditional and digital formats
 • Database indexing and efficient data retrieval
 • Student ID lookups where IDs follow systematic templates
 • Any scenario requiring frequent search operations
 Limitations
 • If data is inserted in sorted order (increasing or decreasing), the tree becomes highly unbalanced
 • Unbalanced trees behave like linked lists, requiring sequential traversal
 • This defeats the efficiency advantage of binary search tree structure

 AVL Trees (Self-Balancing Binary Search Trees)
 Definition: A self-balancing binary search tree where the difference in heights between left and right
 subtrees cannot exceed one for any node.
 Balancing Rule: For any node, |height(left subtree) - height(right subtree)| ≤ 1
 Key Operation - Rotation
 • Automatic rebalancing operation performed during insertion
 • Conceptually similar to restructuring a hanging string and ball system
 • Redistributes nodes to maintain balance without violating BST properties
 • Ensures tree remains balanced during data entry
 How Rotation Works
 • When an imbalance is detected (difference > 1), the middle node is promoted to a higher level
 • Child nodes are rearranged accordingly
 • The tree structure is modified while maintaining BST ordering property
 Advantages
 • Reduced number of hops during search operations compared to unbalanced trees

 • Guaranteed efficient search performance
 • Useful for in-memory indexing in databases
 • Applied in library catalog systems where new disciplines must be accommodated
 Real-World Application: Library cataloging systems use similar rotation concepts where new subjects
 and subdisciplines can be inserted within existing hierarchies without requiring complete
 reorganization.

 Heaps
 Definition: A complete binary tree with additional ordering constraints based on parent-child value
 relationships.
 Important Distinction: A heap is NOT a binary search tree; it does not require left subtree values to
 be less than parent or right subtree values to be greater.
 Two Types of Heaps
 Max Heap:
 • Parent value is always greater than or equal to its children
 • Root node contains the maximum value in the entire tree
 • Property holds recursively for all subtrees
 Min Heap:
 • Parent value is always less than or equal to its children
 • Root node contains the minimum value in the entire tree
 • Property holds recursively for all subtrees
 Implementation Details
 • During insertion, values are rearranged to maintain the heap property
 • Structure remains a complete binary tree after each insertion
 • Values are reordered (not repositioned structurally) to satisfy parent-child constraints
 Primary Application - Priority Queues
 • Max heap: Higher priority elements are processed first (higher numbers get higher priority)
 • Min heap: Lower priority number elements are processed first (priority 1 before priority 2)
 • Medical example: Emergency patients (high priority) are attended before routine cases
 • System processes: System-level tasks take precedence over user-level applications

 Lecture 17: Graph Traversals: Depth First Search
 and Breadth First Search
 Overview
 This lecture covers graph traversal methods, specifically Depth First Search (DFS) and Breadth First
 Search (BFS). Unlike trees where hierarchy is emphasized and a child can have only one parent,
 graphs represent relationships where nodes can have multiple connections. Graph traversals are
 used to search for elements within a graph structure.

 Key Differences Between Graphs and Trees
 • Graphs capture relationships and connections between nodes; a node can have multiple parents
 • Trees represent hierarchy with single parent-child relationships
 • Graphs do not have a designated root node; traversal can start from any node
 • The terms "search" and "traversal" are often used interchangeably since traversal is performed to
    search for specific elements

 Depth First Search (DFS)
 Definition and Concept
 • Explores a graph by going as far as possible along one path before backtracking
 • Visits the first unvisited neighbor and follows it further down until reaching a dead end
 • Once no more unexplored connections exist, the algorithm backtracks one level and repeats
 Applications
 • Finding if any connection exists between two nodes
 • Useful in social network analysis to determine if a person is connected within a network
 • Can establish connections through multiple degrees (friend, friend of friend, etc.)
 Algorithm Implementation Using Stack
 1. Push the starting node onto the stack
 2. Pop the top node and mark it as visited
 3. Find all connected unvisited neighbor nodes of the popped node and push them onto the stack
 4. Repeat steps 2-3 until the stack is empty
 Characteristics
 • Multiple valid DFS paths exist depending on which neighbor is visited first
 • No predetermined order (left-first, right-first) as in tree traversals
 • Both possible paths are correct solutions

 Breadth First Search (BFS)
 Definition and Concept
 • Explores a graph by visiting all nodes at the current depth level before moving to the next depth
    level
 • Starts with a given starting node and progressively expands outward
 • Visits nodes level by level: level 0, then all level 1 nodes, then level 2 nodes, etc.




LECTURE 17 (Recorded)                                                                           Page 29
 Applications
 • Determining the degree of separation between nodes
 • Finding the shortest path between two nodes
 • Identifying how many connections (hops) separate two people in a network
 • Based on the concept of "six degrees of separation"
 Algorithm Implementation Using Queue
 1. Enqueue the starting node into the queue
 2. Dequeue the front node and mark it as visited
 3. Find all connected unvisited neighbor nodes of the dequeued node and enqueue them
 4. Repeat steps 2-3 until the queue is empty
 Characteristics
 • Like DFS, multiple valid BFS paths exist based on the order neighbors are visited
 • Maintains consistent level-by-level traversal regardless of visual graph layout
 • All valid paths following the algorithm correctly are acceptable solutions

 Comparison of DFS and BFS
 Aspect                             DFS                                BFS

 Data Structure                     Stack                              Queue

 Strategy                           Go deep along one path, then       Visit all nodes at current depth
                                    backtrack                          first

 Use Case                           Finding if any connection exists   Finding degree of separation

 Order                              Path-dependent                     Level-dependent



 Important Implementation Notes
 • Understanding stack and queue operations (push, pop, enqueue, dequeue) is essential for
    implementing these traversals
 • Unlike tree traversals which have pre-order, post-order, and in-order variants, graph traversals
    have only two major types: DFS and BFS
 • Starting node is specified in advance; unlike trees, graphs have no inherent root node
 • Both DFS and BFS can be started from any node in the graph, leading to multiple valid traversal
    paths

 Lecture 19: Hash Data Structures and Their
 Applications
 Overview
 Hash data structures are an essential nonlinear data structure that have become increasingly
 important in modern computing. This lecture covers hashing fundamentals, hash table
 implementation, and various applications of hashing in database indexing and cybersecurity.

 Functions and Basic Concepts
 Understanding Functions
 • Functions are organized steps that take inputs and produce outputs based on predefined
    operations
 • Functions are called with input parameters in parentheses and return a value as output
 • Output length can vary depending on the function type and input
 Key Difference - Fixed Length Output
 • Standard functions (like square or uppercase) produce variable-length outputs depending on the
    input
 • Hash functions always produce fixed-length output regardless of input size
 • This fixed-length output is also called a "digest" or "message digest"
 • Hash function outputs are typically alphanumeric (containing both numbers and letters)

 Modulo Function and Hash Calculation
 Understanding Modulo (MOD) Operation
 • Modulo function divides a number by X and returns the remainder as output
 • Syntax: number mod X
 • Examples:
     – 101 mod 10 = 1 (remainder when 101 is divided by 10)
     – 27 mod 5 = 2 (remainder when 27 is divided by 5)
     – 25 mod 5 = 0 (no remainder)
 Determining Hash Values
 • The value of X in modulo function determines the number of unique hash values
 • If you want 10 different hashes, use mod 10
 • If you want 100 different hashes, use mod 100
 • Practical application: mod 10 extracts the last digit of a number

 Hash Tables and Key-Value Pairs
 Hash Table Structure
 • Stored as key-value pairs (technically index-key-value pair)
 • Key: unique identifier used to identify records (e.g., roll number)
 • Value: data associated with the key (e.g., student name)
 • Index: the hash value that points to a location in the table




LECTURE 19 (Recorded)                                                                           Page 35
 Example Application
 • Roll number serves as the key
 • Student name and details serve as the value
 • Using mod 10, the index is determined by the last digit of the roll number
 • Students with roll numbers ending in the same digit are grouped together

 Hash Collision and Resolution
 What is Hash Collision?
 • Occurs when the hash function returns the same hash value for two different inputs
 • Example: Roll numbers B26-SME-001 and B26-SME-011 both end in 1, creating a collision at index
    1
 Collision Resolution - Hash Chaining
 • Uses linked lists to handle multiple records with the same hash value
 • When a collision occurs, new records are chained to existing records at that index
 • Allows efficient storage and retrieval of multiple keys with identical hash values

 Properties of Good Hash Functions for Indexing
 Essential Characteristics
 • Fast Calculation: Hash computation should be quick to enable rapid searches
 • Consistency: Same input should always produce the same hash value
 • Even Distribution: Keys should be spread evenly across different hash positions
 • Fewer Collisions: While some collisions are inevitable, they should be minimized
 • Effective Key Usage: All information in the key should be utilized for searching purposes

 Hash Functions in Cybersecurity
 One-Way Property
 • If input is hashed to produce output, the original input cannot be recalculated from the hash
 • Critical for securing sensitive information like passwords
 Avalanche Effect
 • Even a single-digit change in input must produce a completely different hash
 • Prevents attackers from guessing the original input based on similar hashes
 • Ensures security by making hash outputs unpredictable
 Collision Resistance
 • For cybersecurity purposes, each unique input should ideally produce a unique hash
 • No two different inputs should produce the same hash value
 • Essential for maintaining data integrity and security
 Computing Speed Considerations
 • For integrity checks: Hash calculation should be fast
 • For password storage: Hash calculation should be deliberately slow to prevent password cracking
 • Speed requirements vary based on the application

 Password Storage Using Hashing
 How Password Storage Works
 • User passwords are never stored in their original format
 • Instead, the hash of the password is calculated and stored in the database
 • When a user logs in, their entered password is hashed and compared with the stored hash

 • If hashes match, the password is correct; if not, access is denied
 Security Advantages
 • Even if the database is compromised, passwords cannot be recovered from hashes
 • The one-way property ensures attackers cannot reverse-engineer the original password
 • Avalanche effect means typing a password incorrectly will produce a different hash

 Integrity Checks Using Hash Functions
 Purpose
 • Verify that data or files have not been altered or corrupted during transmission
 Process
 1. Sender calculates hash of original data/file
 2. Hash and data are packaged together and sent to receiver
 3. Receiver unpacks the package and separates data from the hash
 4. Receiver recalculates hash based on received data
 5. Calculated hash is compared with received hash
 6. If hashes match, data integrity is confirmed; if not, data is deemed corrupted
 Advantage
 • Fast hash calculation is suitable for this use case
 • Provides quick verification of data integrity without opening potentially corrupted files

 Key Takeaways
 • Hash functions always produce fixed-length output, distinguishing them from standard functions
 • Hash indexing enables faster database searches through organized placement of records
 • Hash collision can be efficiently resolved using chaining with linked lists
 • Properties required for hash functions vary based on their application
 • Simpler hash functions with potential collisions are suitable for indexing
 • Complex hash functions with collision resistance are essential for cybersecurity applications
 • Password security relies on one-way hashing to prevent password recovery
 • Integrity checks use hash functions to detect data tampering or corruption

 Key Concepts Review
 Linked Lists

 Merkle Tree Protection Layer
 Purpose
 Ensures transaction integrity within blocks and detects any tampering immediately.
 Structure
 • Each transaction is hashed individually (H1, H2, H3, etc.)
 • Pairs of hashes are combined and hashed again to create parent nodes
 • Process continues recursively until reaching the Merkle root
 • Both actual transactions and Merkle root are stored in the block header

 Lecture 21: Search Algorithms and Algorithmic
 Complexity
 Overview
 This module focuses on search algorithms and their complexity analysis. Search is a fundamental
 operation in computer science, present in everyday internet activities such as using search engines,
 shopping platforms, booking systems, and streaming services. Before diving into specific search
 algorithms in subsequent modules, understanding algorithmic complexity is essential to determine
 which approach is most efficient for a given problem.

 Why Search Algorithms Matter
 • Practical Relevance: Every internet activity involves search in some form—from web searches to
    product recommendations to train bookings
 • Efficiency Concerns: Users expect immediate results; delays lead to poor user experience and
    loss of customers
 • Business Perspective: Companies must evaluate solutions based on feasibility, cost (computing
    resources), speed of delivery, and scalability

 Algorithmic Complexity Fundamentals
 Definition and Purpose
 Algorithmic complexity describes how much time an algorithm requires as the input size increases.
 The focus is on the growth rate rather than exact execution time in seconds or hours.
 Key Point: We are concerned with scalability—if input size increases from 100 to 10 lakh elements,
 how does the algorithm's performance change?
 Why Complexity Matters
 • Different algorithms can solve the same problem but require vastly different resources
 • Time complexity is prioritized over space complexity because faster responses improve user
    satisfaction
 • Managers and programmers need to understand algorithmic efficiency for system evaluation

 Types of Complexity Analysis
 When analyzing algorithms, three scenarios are considered:
 • Best Case: The situation where the algorithm finds the solution very quickly with minimal work
 • Worst Case: The situation requiring maximum effort to find the solution
 • Average Case: The typical amount of work required, falling between best and worst cases
 Example: In a numbered housing society with 24 houses accessed through gate A, houses 3 and 4
 represent the best case (closest to gate), houses 19 and 24 represent the worst case (farthest from
 gate), and houses 7-18 represent the average case.

 Big O Notation
 Big O notation describes the order of magnitude of how algorithmic work grows with input size. It
 answers the question: "If I increase the input size, in what proportion does the time requirement
 increase?"

 • Slow algorithm = High complexity = Faster growth rate (O(n2), O(2n), O(n3))
 • Practical Analogy: The chess legend illustrates exponential growth—doubling grains on each

    unmanageable.

 Complexity of Data Structure Operations
 Arrays
 • Access by Index: O(1) — Direct access to known position
 • Search (linear): O(n) — Must check elements sequentially if position unknown
 • Insert at End: O(1) — Always appends without moving other elements
 • Insert at Beginning: O(n) — Requires shifting all elements
 • Insert in Middle: O(n) — Requires shifting subsequent elements
 • Update by Index: O(1) — Direct access to known position
 • Update by Search: O(n) — Must search first
 • Delete by Index: O(1) — Direct removal from known position
 • Delete by Search: O(n) — Must search first
 Linked Lists
 • Insert at End: O(1) — Simply connect new node to last node's pointer
 • Insert at Beginning: O(n) — May require search
 • Insert in Middle: O(n) — Must search for insertion point
 Stacks
 • Push: O(1) — Always adds at top; location is fixed

 • Pop: O(1) — Always removes from top; location is fixed
 • Search: O(n) — Must pop elements until finding target
 Queues
 • Enqueue: O(1) — Always adds at end; location is fixed
 • Dequeue: O(1) — Always removes from front; location is fixed
 • Search: O(n) — Must dequeue elements until finding target
 Trees
 • General Tree Traversal/Search: O(n) — Must visit every node; increases proportionally with tree
    size
 • Binary Search Tree Search: O(log n) — At each level, half the remaining nodes are eliminated by
    choosing one branch
 • Reason: Left subtree contains smaller values, right subtree contains larger values; this property
    allows subdivision of the problem into one relevant sub-problem
 Graphs
 • Traversal/Search (BFS or DFS): O(V + E) — Must potentially visit all vertices and edges
     – V = number of vertices
     – E = number of edges

 Practical Recommendations
 Business Preference Order
 1. O(1) — Ideal but rarely achievable in real scenarios
 2. O(log n) — Excellent; highly scalable
 3. O(n log n) — Good; manageable for most applications
 4. O(n) — Acceptable; straightforward scaling
 5. O(n2), O(2n), O(n3) — Problematic; avoid unless necessary
 Handling Highly Complex Algorithms
 When algorithmic complexity becomes O(n2) or exponential, businesses often employ
 heuristics—rules of thumb that provide good enough (though not optimal) solutions rather than
 perfect answers. This pragmatic approach balances computational feasibility with practical results.

 • Algorithmic complexity measures growth rate, not absolute time
 • Big O notation enables comparison of algorithms across different input sizes
 • Scalability is crucial—how does performance change as data volume increases?
 • Choice of algorithm directly impacts system responsiveness and user experience
 • O(1) and O(log n) complexities are preferable; exponential complexities should be avoided
 • Understanding data structure operations and their complexities is fundamental to choosing
    appropriate solutions

 Lecture 22: Search Algorithms Overview
 This lecture continues the module on search algorithms, building on previous discussions about
 algorithm complexity and search operations across different data structures. The session covers five
 key search strategies: linear search, binary search, jump search, exponential search, and
 hash-based search.

 Linear Search
 • Definition: Searches sequentially through elements one by one, starting from the first element
 • Requirement: Works on both sorted and unsorted data
 • Process: Compare each element with the search term; move to the next element if no match
 • Time Complexity: O(n) - effort increases proportionally with data size
 • Application: Works on arrays, linked lists, trees, and graphs
 • Limitation: Becomes time-consuming with large datasets (e.g., searching millions of records)

 Binary Search
 • Definition: Algorithm that divides a sorted list into halves to locate elements
 • Requirement: Data must be sorted in increasing order
 • Process:
     1. Start at the middle element
     2. Compare with search term
     3. If smaller, search the right half; if larger, search the left half
     4. Repeat with the middle of the remaining segment
 • Time Complexity: O(log n) - divides the problem into smaller sub-problems
 • Key Difference from Binary Search Tree: Binary search is an algorithm applicable to any sorted
    list, while a Binary Search Tree (BST) is a data structure that inherently maintains order through
    its structure

 Jump Search
 • Definition: Algorithm that jumps by a fixed number of positions rather than checking sequentially
 • Requirement: Data must be sorted
 • Jump Size Calculation: Determined by √n (square root of data size)
 • Example: For 100 elements, jump size is 10; for 9 elements, jump size is 3
 • Process:

     1. Jump by fixed intervals until the search term is exceeded
     2. Return to the previous position
     3. Perform linear search forward from that point
 • Time Complexity: O(√n) - divides data into √n blocks
 • Advantage: Divides problem into manageable sub-problems without the large jumps of binary
    search

 Exponential Search
 • Definition: Algorithm that exponentially increases jump size until the search term is found
 • Requirement: Data must be sorted
 • Jump Pattern: Starts with jump of 1, then doubles successively (1, 2, 4, 8, 16...)
 • Process:
     1. Make exponentially larger jumps until the search term is exceeded
     2. Once the range is identified, perform binary search within that block
 • Key Difference from Jump Search:
     – Jump search uses fixed-size jumps with linear search within blocks
     – Exponential search uses increasing jumps with binary search within blocks
 • Time Complexity: O(log n) - combines exponential jumps with binary search
 • Advantage: Efficient for very large and continuously growing databases

 Hash-Based Search
 • Definition: Uses a hash function to calculate an index location for data storage and retrieval
 • Hash Function: Converts input values into unique indices (e.g., mod 10 returns 0-9)
 • Collision Handling: Uses chaining method where multiple values pointing to the same index are
    linked like a linked list
 • Process:
     1. Calculate hash value of the search term
     2. Go directly to that index
     3. If collision exists, search through the chain linearly
 • Time Complexity:
     – Average case: O(1) - fixed number of steps regardless of database size
     – Worst case: O(n) - occurs when all data points to the same index (collision intensive)
     – Balanced chain scenario: O(log n) - if chains are organized as balanced trees
 • Advantage: Fastest search method when hash function distributes data evenly
 • Note: Does not require sorted data

 Tree Types
 General Tree
 • Definition: A tree where the number of children per node is not fixed; each node can have zero,
    one, two, or many children
 • Key Property: Each child has exactly one parent
 • Real-World Applications:
     – Folder structures (directories and subdirectories in file systems)
     – Family trees
     – Organization hierarchies (executives, managers, employees)
     – Biological taxonomy (kingdom, phylum, class, order, etc.)

 Binary Tree
 • Definition: A tree where each node has at most two children (left and right child)
 • Key Property: The number of children can be 0, 1, or 2
 • Applications:
     – Tournament structures (tennis, badminton—individual sports with knockout rounds)
     – Decision trees and flowcharts (yes/no branching)
     – Expression evaluation

 Complete Binary Tree
 • Definition: A binary tree where all levels are completely filled except possibly the last level, which
    is filled from left to right
 • Constraint: All nodes except possibly the last level have exactly two children
 • Characteristic: If a node exists on the last level, all positions to its left must be filled

 Binary Search Tree (BST)
 • Definition: A binary tree with an additional property where left child value < parent value and
    right child value ≥ parent value
 • Key Characteristics:

     – Enables efficient searching similar to searching in a physical dictionary
     – If values are inserted in sorted order, the tree can become skewed (like a linked list), reducing
       search efficiency
     – Used for quick lookup operations

 AVL Tree
 • Purpose: Solves the skewness problem of Binary Search Trees
 • Key Property: Maintains balance by ensuring the height difference between left and right subtrees

 • Mechanism: Uses rotations to rebalance the tree when height difference exceeds one level

 Hashing
 Basic Concept
 • Hash Function: Takes an input of any size and produces a fixed-length output
 • Key Property: The output length remains constant regardless of input size
 • Simple Example: Using modulo (mod) operator to find remainder when dividing by a number

 Modulo Function

 • Example:

 • Possible Values: For mod n, possible outputs are 0 to (n-1)

 • Application: Database indexing for efficient data retrieval on billions of records

 Hash Collision
 • Definition: Occurs when two different inputs produce the same hash output
 • Example: Numbers ending in 2 (12, 22, 32) all have hash value 2 using mod 10

 • Solution - Chaining: Link items with the same hash value using linked lists, pointing subsequent

 • Deterministic: Same input always produces same output

 • Blockchain stores copies of all blocks across multiple nodes in a network

 • Single node tampering is detected by comparing with other nodes
 Consensus Mechanism

 Lecture 24: Network Search Algorithms: Overview
 and Implementation
 This lecture concludes Module 4 on search algorithms by exploring search within nonlinear data
 structures, specifically networks represented as graphs and trees.

 Introduction to Network Search
 • Network search extends search concepts beyond linear data structures to include trees and
    graphs
 • A network consists of nodes (vertices) and edges connecting them
 • Search in networks often involves finding paths between nodes rather than just locating
    individual elements

 Traversal Methods as Search Techniques
 Tree Traversals
 • Pre-order traversal: Root, left, right (reads data as traversal occurs)
 • In-order traversal: Left, root, right
 • Post-order traversal: Left, right, root
 • Traversals inherently perform search by reading node data during the process
 Level-Order Traversal (Breadth-First Search)
 • Moves level by level from top to bottom, left to right
 • Useful for understanding network hierarchy and levels
 • Implemented using a queue data structure
 • Helps identify how many hops are needed to reach different nodes

 Graph Search Algorithms
 Depth-First Search (DFS)
 • Traverses as far as possible along each branch before backtracking
 • Useful for understanding complete network topology, especially when identifying new nodes or
    leaves
 • Implemented using a stack data structure
 • Effective for mapping network structure when new systems or connections are added
 Breadth-First Search (BFS)
 • Traverses level by level based on hop count rather than geographic location
 • Helps understand hierarchical network topology (e.g., client-based systems, intermediate servers,
    main servers)
 • Useful for identifying levels within a network structure

 Shortest Path Problem
 Real-World Applications
 • Simply knowing network topology is insufficient for many practical applications
 • Once familiar with a network, users need targeted navigation rather than complete exploration
 • Shortest path algorithms help find optimal routes between specific source and destination nodes

 Defining "Shortest"
 • Shortest does not necessarily mean the shortest distance
 • Cost variables can include:
     – Distance (in kilometers)
     – Time taken
     – Monetary cost (toll charges)
     – A combination of multiple factors
 • Path selection depends on specific requirements (e.g., avoiding toll roads, faster travel time
    despite longer distance)

 Dijkstra's Algorithm
 Overview
 • Named after Dutch computer scientist Edsger Dijkstra (pronounced "DIK-struh")
 • Finds the shortest path from a source node to all other nodes in a weighted graph
 • Works only with positive weights—negative edge weights are not permitted
 Basic Assumptions
 • Each edge has an associated cost (weight)
 • All weights must be non-negative
 • Cost represents the variable being optimized (distance, time, toll charges, etc.)
 Algorithm Steps
 1. Initialize: Set source node distance to 0; set all other nodes to infinity
 2. Select unvisited node: Choose the unvisited node with the smallest known distance
 3. Update distances: For each neighbor, check if there is a shorter path through the current node
 4. Mark as visited: Once a node's shortest distance is finalized, mark it as visited
 5. Repeat: Continue until all nodes are visited or the destination is reached
 Worked Example
 Starting from node A with weighted edges:
 • Direct path A→B: cost 4
 • Direct path A→C: cost 2
 • Path A→C→B: cost 2+1=3 (shorter than direct path)
 • Path A→C→D: cost 2+5=7
 • Path A→C→B→D: cost 3+3=6 (shorter than previous)
 • Shortest path to each node is finalized once visited
 Key Characteristics
 • Calculates shortest distances from one specific starting node to all other nodes
 • Does not provide absolute shortest distances between all node pairs
 • Results vary depending on which node is selected as the starting point

 Practical Applications
 Spoke and Hub Model
 • Used by courier companies and logistics firms to optimize delivery networks
 • Instead of connecting every city to every other city, businesses create hubs with spoke cities
 • Example: Package from Jodhpur to Somnath travels Jodhpur→Jaipur→Delhi→Somnath
 • Dijkstra's algorithm calculates shortest distances between major hubs
 • Reduces overall network complexity and cost

 Alternative Network Search Algorithms
 A* Algorithm
 • Combines actual distance cost with heuristic guidance (sense of direction)
 • Determines if travel is in the correct direction (e.g., traveling south instead of north)
 • More optimal than Dijkstra's algorithm
 • Widely used in GPS navigation systems
 Other Variants
 • Uniform Cost Search: Explores lowest-cost paths; useful for avoiding tolls or specific constraints
 • Bidirectional Search: Searches simultaneously from source and destination to find meeting point
 • Floyd-Warshall Algorithm: Finds shortest paths between all pairs of nodes
 • Bellman-Ford Algorithm: Works with both positive and negative edge weights
 • Prim's Algorithm: Connects all nodes with minimum total connection cost (minimum spanning
    tree)
 • Kruskal's Algorithm: Creates minimum-cost connected network; alternative to Prim's algorithm
 Algorithm Selection Criteria
 • Dijkstra's Algorithm: When shortest path needed from one source to all destinations
 • Bellman-Ford: When negative edge weights exist
 • Prim's/Kruskal's: When connecting all nodes with minimum total cost
 • Floyd-Warshall: When all-pairs shortest paths are required
 • A*: When directional heuristics can optimize search

 Key Takeaways

 • Dijkstra's algorithm is a fundamental approach for single-source shortest path problems
 • Works on weighted graphs with non-negative weights
 • Edge weights represent various costs: distance, time, toll charges, or combinations
 • Different algorithms serve different business scenarios and network requirements
 • Most real-world applications already have implemented variants or combinations of these
    algorithms

 Lecture 25: Introduction to Sorting Algorithms
 and Bubble Sort
 Overview
 This lecture introduces the final module on sorting algorithms, focusing on understanding what
 sorting is and how the bubble sort algorithm works. Sorting is fundamental in computer science,
 essential for both data organization and enabling efficient searching.

 What is Sorting?
 • Definition: Sorting is the process of arranging elements in a specific order (ascending,
    descending, or based on specific parameters)
 • Parameters: Elements can be sorted by various criteria such as numerical values, alphabetical
    order, relevance, price, quality, or any custom parameter
 • Connection to Searching: Most search algorithms assume data is already sorted, making sorting a
    prerequisite for efficient searching
 • Real-World Applications:
     – E-commerce platforms sort products by relevance, price, quality, and other metrics
     – Flight booking systems sort results by price, travel time, and other criteria
     – Academic reporting requires sorting marks from highest to lowest for grade assignment
     – Multiple sorting parameters enhance user experience and decision-making

 Bubble Sort Algorithm
 Basic Concept
 • The name derives from the behavior of air bubbles rising in water
 • Core Idea: Elements gradually move to their correct positions through successive comparisons
    and swaps
 • Lighter elements (smaller values) move toward the beginning; heavier elements (larger values)
    move toward the end
 Classic Method (Largest Element to the End)
 1. Start from the first element and compare it with the next element
 2. If the first element is larger, swap their positions
 3. Move to the next pair and repeat
 4. After each pass (complete iteration through the list), the largest unsorted element moves to its
     correct position at the end
 5. Repeat the process, requiring one fewer comparison in each subsequent pass
 6. Total passes needed equals the number of elements in the list
 Step-by-Step Example
 Using the list: [10, 5, 8, 4, 3, 2]
 Pass 1: Compare and swap adjacent elements
 • 10 > 5 → swap → [5, 10, 8, 4, 3, 2]
 • 10 > 8 → swap → [5, 8, 10, 4, 3, 2]
 • 10 > 4 → swap → [5, 8, 4, 10, 3, 2]
 • 10 > 3 → swap → [5, 8, 4, 3, 10, 2]

 • 10 > 2 → swap → [5, 8, 4, 3, 2, 10]
 • Result: Largest element (10) is now in correct position
 Pass 2 onward: Repeat with reduced comparisons since last element is already sorted
 • After Pass 2: Two largest elements in correct positions
 • Continue until entire list is sorted
 Alternative Method (Smallest Element to the Front)
 • Start from the last element and compare with the previous element
 • Focus on finding the smallest element and moving it left
 • After each pass, the smallest unsorted element moves to its correct position at the beginning
 • This variant produces the same final result through a different approach
 Sorting Non-Numerical Data
 Bubble sort works on any comparable data (alphabetical, strings, etc.)
 • Example with names: [Mohan, Ram, Sham, Lakshman, Arjun, Bheem]
 • Capital letters are compared alphabetically (A < Z)
 • Same comparison and swapping logic applies

 Time Complexity Analysis
 Calculation
 • Pass 1: n comparisons (where n is the number of elements)
 • Pass 2: n - 1 comparisons
 • Pass 3: n - 2 comparisons
 • Final pass: 1 comparison
 Total comparisons = n + (n-1) + (n-2) + ... + 1 = n(n-1)/2 = ½n2 - ½n
 Big O Notation
 Using Big O rules:
 • Discard lower-order terms: -½n is negligible compared to n2
 • Remove numerical constants: ½ is removed
 • Result: O(n2) - Quadratic complexity
 Impact on Performance
 • Small lists (5-6 elements): Manageable with ~25 operations
 • Larger datasets: Complexity grows rapidly (10,000 elements = ~100 million comparisons)
 • Conclusion: Unsuitable for large datasets or business applications despite logical simplicity

 Key Takeaways
 • Sorting arranges data in a specific order based on parameters (numerical, alphabetical,
    relevance, etc.)
 • Bubble sort uses successive comparisons of adjacent elements with swaps to order data
 • Each pass moves one element to its correct final position
 • Multiple passes required equal to the list size
 • Time complexity is O(n2), making it impractical for large datasets
 • Next algorithms will address efficiency concerns for larger data sets
