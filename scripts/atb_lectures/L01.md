# Lecture 1: 1: Introduction to Algorithmic Thinking

Lecture 1: Introduction to Algorithmic Thinking
This lecture introduces the foundational concepts of algorithms using a no-code approach, designed for
students from any educational background. The course focuses on understanding the logic and building
blocks of algorithms that power modern business applications, rather than teaching programming.
Understanding Algorithms Through Everyday Examples
Tea Making Exercise
Algorithms can be understood through familiar, real-world tasks like making tea
An algorithm is a series of organized steps to convert input data into a desired output
The sequence of steps may vary based on personal preference, but the final outcome remains
consistent
The process demonstrates how algorithms function in everyday situations
Core Algorithmic Terminology
Data
Represents the actual values you work with during algorithm execution
Changes with each iteration of the algorithm depending on the specific situation
Example: The amount of water and milk needed varies based on the number of people being served
Variables
Constructs that hold data during computation
Similar to physical vessels (saucepan, teacup) in the tea-making example
Used to store values that may change throughout algorithm execution
Algorithm
A series of organized steps to complete a specific task
Steps may vary in sequence, but all work together to achieve the desired output
Becomes increasingly complex as more details, checks, and conditions are added
Functions
Subgroups of organized steps that are part of a larger algorithm
Represent frequently used tasks with consistent steps across multiple algorithms
Example: Adding numbers, calculating averages, or providing heat in cooking
Remain the same regardless of where they appear in different algorithms
Flowchart Representation
Basic Flowchart Symbols
Rounded Rectangle: Start and end points
Rectangle: Processing statements and steps
Trapezoid/Slanted Rectangle: Input and output operations

Creating Accurate Flowcharts
Simple flowcharts contain only processing steps
More refined versions differentiate between input, processing, and output operations
Complex flowcharts incorporate decision loops where the algorithm revisits steps based on conditions
Example: Tea-making flowchart with decision loop checking if tea is sufficiently brewed
Real-World Business Application: ATM Cash Dispensing
Algorithm Steps
Check and read card details (input)
Request PIN entry (input)
Verify PIN against stored data (decision point)
If PIN incorrect: end process
If PIN correct: request withdrawal amount (input)
Check account balance (decision point)
If insufficient balance: end process
If sufficient balance: release cash (function)
End process
Key Observations
Not all paths in an algorithm are executed in a single run
Depending on decision outcomes, certain paths are taken while others are skipped
Complex operations like "release cash" are handled as separate functions with their own algorithms
Algorithm Complexity and Evolution
Simplification and Detail Addition
All algorithms are simplifications of real-world processes
Algorithms begin simply and become more complex as details are added
Real-life decisions often involve intuitive steps that are difficult to codify completely
Example: "Add water" implicitly includes finding the water, locating the container, and filling it
Deterministic vs. Complex Systems
Modern business systems are generally deterministic and calculation-based, making them easier to
algorithmize
Physical systems (robotics, autonomous vehicles) are more complex due to real-time decision-making
requirements
Business applications require fewer considerations about physical movement
Continuous Evolution
Algorithms and software applications are regularly updated with new features and enhanced security
checks
Each update adds new functions, additional checks, and refined conditions

Key Takeaways
Algorithms are series of steps designed to complete specific tasks
Both plain English and flowchart representations effectively communicate algorithmic logic
Algorithm complexity increases with added details, conditions, and checks
In any single execution, an algorithm typically follows only one path based on decision outcomes
Understanding algorithms requires recognizing how they function in both everyday situations and
business applications
Algorithms form the foundation of modern software and business systems
