# Lecture 29: 29: Merge Sort: A Divide and Conquer Sorting Algorithm

Lecture 29: Merge Sort: A Divide and Conquer Sorting
Algorithm
This lecture introduces merge sort, an efficient divide and conquer sorting algorithm designed to overcome
the limitations of previous sorting methods (bubble sort, selection sort, and insertion sort), which all have
O(n²) complexity. Merge sort achieves O(n log n) complexity, making it practical for sorting large datasets.
Limitations of Previous Sorting Algorithms
Bubble sort, selection sort, and insertion sort all have O(n²) complexity
As list size increases, processing time becomes impractical
These algorithms involve many swap operations that increase complexity
Divide and Conquer Approach
Breaks a large problem into smaller subproblems
Solves subproblems independently
Combines results to obtain the final solution
Merge sort and quick sort are examples of divide and conquer algorithms
How Merge Sort Works
Phase 1: Splitting Stage
Divide the list into two roughly equal parts
Term "roughly equal" accounts for odd-numbered elements (e.g., 15 elements = 8 + 7)
Continue dividing each part recursively until every element stands alone
No sorting occurs during this phase, only division
Phase 2: Merging Stage
This is where actual sorting occurs through the following steps:
Merging Process:
Take two sorted parts at a time
Compare the first item of both parts
Place the smaller item into a new sorted list
Move to the next item in the part from which the smaller item was taken
Continue comparing front items of each part
When one part becomes empty, add all remaining items from the other part directly (already sorted)
Example with Numbers [10, 5, 8, 4, 3, 2, 7, 6]
After splitting: individual elements
First merge round: [5,10], [4,8], [2,3], [6,7]
Second merge round: [4,5,8,10], [2,3,6,7]
Final merge: [2,3,4,5,6,7,8,10]

Handling Odd-Numbered Lists
No algorithm changes required
When dividing an odd number of elements, parts will be unequal
Example: 7 elements → divide into 4 and 3
Division continues until each element is isolated
Time Complexity Analysis
Dividing stage: O(log n) — successive halving of the list
Merging stage: O(n) — comparison operations required at each level
Overall complexity: O(n log n) — significantly better than O(n²)
Space Complexity
Higher space requirement compared to previous sorting methods
Requires additional memory to create new lists during merging
Unlike previous algorithms that swapped within the same array, merge sort creates separate lists
Trade-off: uses more memory but achieves better processing time
Advantages
No swap operations required
Only comparison operations are performed
Efficient for large datasets
Predictable O(n log n) performance
Variants of Merge Sort
Top-Down Two-Way Merge Sort (Classical)
Splits larger list into two smaller parts progressively
Most commonly used variant
Bottom-Up Merge Sort
Useful when individual items already exist independently
Begins with merging stage without splitting
Practical when data arrives pre-segmented
Three-Way Merge Sort
Divides list into three parts instead of two
Same logic applies with increased partition count
Natural Merge Sort
Detects already sorted sections within data
Merges only the necessary parts
Useful for partially sorted datasets
Parallel Merge Sort
Executes sorting of different parts simultaneously

Can use multiple processors or threads
Each part sorted in parallel, then merged
Significantly reduces processing time for very large datasets
Practical Applications
Sorting customer or product lists
Alphabetically organizing large datasets by splitting at letter boundaries
Processing millions of records efficiently
Can be complemented with additional server memory for optimal performance
Useful in environments with parallel processing capabilities
Key Takeaways
Merge sort is a divide and conquer algorithm that divides the sorting problem into smaller problems
Creates smaller sorted lists and then merges them in order
Complexity is O(n log n), significantly better than O(n²)
Requires extra memory but provides superior processing time for large datasets
Multiple variants exist to optimize performance for different scenarios and data characteristics
