Lecture 20: Conclusion of Non-Linear Data Structures:
Introduction to Blockchain
This lecture concludes the non-linear data structures module by exploring blockchain technology, which
applies concepts from linked lists, hashing, trees, and graphs. Blockchain is introduced as a practical
application that combines multiple data structure concepts to create a secure, decentralized system for
storing and managing transactions.
Key Concepts Review
Linked Lists
Linear data structure where each node points to the next node's memory address
Nodes are added sequentially, typically starting from a head node
Example: Music playlists function as linked lists
Reading proceeds forward from the head node
Cryptographic Hash Functions
Takes variable-length input and produces fixed-length output
Key properties include:
Collision-free: Unique inputs produce unique outputs
Non-reversible: Cannot calculate input from output
Sensitive: Even changing a single bit completely changes the output
Blockchain Structure and Components
Basic Block Structure
Header: Contains hash of previous block, hash of current block, and Merkle root
Transactions: Set of operations stored chronologically within each block
Genesis Block: First block in a blockchain (equivalent to head node in linked lists)
Chain Formation: Each block stores the hash of the previous block, creating logical connections
How Blocks Connect
Unlike linked lists that use memory addresses, blockchain uses cryptographic hashes
Each block contains: previous block's hash, current block's hash, and transactions
Reading the blockchain proceeds backward by following hashes from newest to oldest blocks
Merkle Tree Protection Layer
Purpose
Ensures transaction integrity within blocks and detects any tampering immediately.
Structure
Each transaction is hashed individually (H1, H2, H3, etc.)
Pairs of hashes are combined and hashed again to create parent nodes

Process continues recursively until reaching the Merkle root

Tampering Detection
If any transaction is modified, its hash changes
This cascades upward, changing the Merkle root
Any modification is immediately detectable because the root will not match the recalculated value

Decentralization and Tamper-Proofing
How Blockchain Achieves Tamper-Proofing
Multiple nodes store identical copies of all blocks
Nodes compare their block copies with each other
If one block is modified, its hash changes, breaking the chain
The modified block is identified and compared against copies in other nodes
The majority copy (typically 51%+) is considered authentic
Modified blocks are discarded, maintaining integrity across the network
Consensus Mechanism
Protocol used by blockchain nodes to agree on the authentic version of blocks
Ensures all nodes maintain identical copies of valid blocks
Enables nodes to validate and share transactions simultaneously
Public vs. Permissioned Blockchains
Permissioned Blockchain: Specific nodes designated by an organization (e.g., enterprise
blockchains)
Public Blockchain: Any node can join by following network protocols (e.g., Bitcoin)
May require proof of work (solving computational problems)
May require proof of stake (providing storage or processing power)
Tree and Graph Application in Blockchain
Trees: Used in the form of Merkle trees to verify transaction integrity
Graphs: Graph traversal algorithms determine if a node is part of the blockchain network and validate
network connections

Blockchain Node Functions
A blockchain node must:
Follow the established blockchain protocol
Connect to other nodes in the network
Use cryptographic keys and hashes for identity and validation
Validate incoming blocks
Store copies of valid blocks
Broadcast valid blocks and transactions to other nodes simultaneously
Common Blockchain Applications
Cryptocurrencies
Most well-known application (Bitcoin, Ethereum, etc.)
Technically tokens rather than currency (not issued by central banks)
Community agreement establishes perceived value
Decentralized ledger prevents tampering
Smart Contracts
Self-executing contracts with conditions built into code
Automatically execute when specified conditions are met
Tamper-proof storage on blockchain eliminates need for extensive legal oversight
Reduces dependency on lawyers and legal fees
Example: Construction contracts with automatic penalty clauses
Emerging Applications
Revenue Records: Land registries and property records
Health Records: Electronic health records and medical histories
Supply Chain: Tracking product origin and authenticity
Voting Systems: Secure, tamper-proof voting records
Implementation Challenges
Despite blockchain's robustness, widespread adoption faces barriers:
High Implementation Costs: Expensive infrastructure and maintenance requirements
Return on Investment: Benefits must justify significant financial investment
Limited Scalability: Current systems struggle with transaction volume
Regulatory Uncertainty: Legal frameworks still developing
Current adoption is limited to cryptocurrency and smart contracts, with pilot programs in revenue and
health record management. Widespread implementation will increase as costs decrease and return on
investment improves.
Key Takeaways
Blockchain combines linked list structure with cryptographic hashing for secure data management
Understanding blockchain requires knowledge of linked lists, hash functions, trees, and graphs
