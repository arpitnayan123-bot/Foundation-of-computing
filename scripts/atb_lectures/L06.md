# Lecture 6: 6: Introduction to Linear Data Structures and Arrays

Lecture 6: Introduction to Linear Data Structures and
Arrays
This lecture introduces linear data structures, focusing on arrays as the primary example of organizing
data sequentially for improved accessibility and management.
Overview of Data Concepts
Data: Actual values you work with during computation
Variables: Storage locations for data during program execution
Limitation of simple variables: Declaring individual variables for each piece of data (e.g., sub1, sub2,
sub3) becomes cumbersome and inefficient when dealing with multiple instances of similar data types
Linear Data Structure Definition
Linear data structures arrange elements sequentially in an ordered manner, where each element is
positioned relative to others. The key benefit is that if you can access one element, you can find adjacent
elements through a defined relationship. This provides a structured way to organize and access data
efficiently.
Real-world analogy: Comparing traditional addresses (requiring knowledge of landmarks) with modern
structured addresses using house numbers and postal codes, which allow direct access regardless of
ownership or location changes.
What Are Arrays?
Arrays are a fundamental linear data structure with the following characteristics:
Homogeneous data type: All elements must be the same data type (all integers, all floats, or all
characters—cannot mix types)
Indexed access: Individual elements are identified using index numbers, enabling direct access
without reading sequentially
Index convention: Indexing begins at 0, so the first element is at index 0, the second at index 1, and
so forth
Contiguous memory storage: Elements are stored in continuous memory locations
Array Declaration Syntax
C/C++ format:
int sub[5] = {60, 65, 70, 50, 60};
(Requires explicit data type and size specification)
Python format:
sub = [60, 65, 70, 50, 60]
(Data type is inferred from content; more flexible)

Single-Dimensional Arrays
Store elements in a single row with indices from 0 to n-1
Example use case: Storing marks of five subjects for one student
Direct access example: sub[3]  retrieves the value at index 3
Multi-Dimensional Arrays
Two-dimensional arrays extend the concept to handle more complex data organization:
Structure: Rows represent one dimension (typically indexed as i), columns represent another (indexed
as j)
Use case: Storing marks for multiple subjects across multiple students
Index notation: array[i][j]  where i is the row index and j is the column index
Example: A 7×5 array stores marks for 7 students across 5 subjects, accessed as sub[2][1]  for row
index 2, column index 1
Note: Arrays can theoretically have n dimensions, but two-dimensional arrays are most practical for
typical applications. Higher dimensions increase programming complexity.
Basic Array Operations
1. Read/Access
Direct access: Retrieve a value from a known index position instantly
Sequential access: Read elements one by one, useful for aggregating data (e.g., calculating weekly
sales totals)
Performance: Instantaneous if index is known
2. Search
Linear search: Start at index 0 and compare each element sequentially with the search term
Process: Increment index and repeat comparison until the element is found or array ends
Performance: Depends on element position; faster if element is near the beginning, slower if near the
end
3. Insert
At the end: Simple operation if array has available space
At beginning or middle: Requires shifting all subsequent elements forward to create space
Example: Inserting at index 0 requires moving element at index 4→5, 3→4, 2→3, 1→2, 0→1
Performance: Time-consuming if insertion requires shifting multiple elements
4. Update
Known location: Directly go to the index and replace the value; instantaneous operation
Unknown location: Combine search with update; requires finding the element first, then updating
Example: Updating inventory when stock is sold (15 units → 10 units after selling 5)
5. Delete
Operation: Remove or set a value at a specific index to null (not zero, but "nothing stored")
Known location: Direct deletion is instantaneous
Unknown location: Requires searching first, then deleting

Advantages of Arrays
Easy to understand: Simple extension of the single-variable concept
Memory efficient: Continuous storage allocation for a known fixed size
Fast direct access: Instantaneous retrieval when index is known
Foundation for other structures: Many advanced data structures are built upon arrays
Ideal for predictable datasets: Excellent when data size is known in advance
Limitations of Arrays
Fixed length: Size must be declared at creation and cannot be easily extended
Size prediction challenges: Too large a declaration wastes memory; too small causes overflow
Resizing complexity: Cannot simply add elements; requires creating a new array, copying data, then
inserting new values
Contiguous memory requirement: Must use continuous memory blocks; cannot work with scattered
memory locations
Inefficient with frequent modifications: Operations combining search with update/delete consume
significant time and resources
Search performance degradation: Sequential searching becomes increasingly time-consuming as
array size grows
Key Takeaways
Linear data structures arrange elements sequentially for structured, efficient access
Arrays store homogeneous data types in indexed, contiguous memory locations
Single-dimensional arrays suit simple sequential data; multi-dimensional arrays handle complex,
tabular data
Direct index-based access is highly efficient; sequential searching is resource-intensive
Arrays excel with predictable, fixed-size datasets but struggle with dynamic data or frequent
modifications
Understanding operation performance is crucial for choosing appropriate data structures for specific
use cases
