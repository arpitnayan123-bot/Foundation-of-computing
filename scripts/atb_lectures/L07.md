# Lecture 7: 7: Introduction to Linked Lists and Linear Data Structures

Lecture 7: Introduction to Linked Lists and Linear Data
Structures
This lecture continues Module 2 on linear data structures, focusing on linked lists as the second major
linear data structure after arrays. The session explains why linked lists are necessary and how they differ
from arrays in terms of flexibility and use cases.
Overview of Linear Data Structures
Linear data structures arrange elements sequentially with a logical order
Elements are connected so that accessing one item allows movement to adjacent items
Arrays use indexing to provide direct access to elements
Limitations of Arrays
Fixed Size Requirement: Array size must be defined in advance; adding elements beyond the initial
size requires redefining the entire array
Inefficient Modifications: Deleting or inserting elements in the middle requires shifting other
elements or creating null spaces
Static Structure: Limited flexibility when data requirements change
Best Use Case: Arrays work well when you know the exact number of elements needed in advance
and direct access is a priority
Need for Linked Lists
Linked lists address the limitations of arrays in scenarios where:
The number of elements is unknown in advance
Frequent addition, deletion, and rearrangement of items is required
Flexibility and dynamic sizing are essential
Practical Example - Music Playlists:
Users can add or remove songs without predefined limits
Songs can be reordered based on preference
New songs can be inserted at any position in the sequence
Fundamental Concepts of Linked Lists
Basic Structure
Each linked list starts with a head node (the entry point, similar to a bus stop)
Each node contains data and a connection (pointer/address) to the next node
The last node points to null, indicating the end of the list
Elements are not stored in contiguous memory; they can be scattered anywhere in memory
The connections between nodes create the logical sequence, not physical proximity

Key Difference from Arrays
Arrays store elements in consecutive memory locations
Linked lists use pointers/addresses to link elements regardless of their physical memory locations
Types of Linked Lists
Single Linked List
Nodes connect in one direction only (forward)
Allows traversal from head to end
Useful for sequential playback (play next functionality)
Doubly Linked List
Nodes have connections in both directions (forward and backward)
Enables movement both forward and backward through the list
Implements features like "play previous" in music players
Circular Linked List
The last node points back to the head instead of null
Creates a loop that returns to the beginning when reaching the end
Useful for implementing repeat or shuffle features
Common in menu systems and cyclical applications
Operations on Linked Lists
Adding Elements
New elements can be inserted anywhere in the list
The process involves placing the new element in any available memory location
Pointer connections are adjusted so that the previous node points to the new node, and the new node
points to the former next node
No need to shift or reorganize existing elements
Deleting Elements
Removal requires only adjusting the pointer connections
The previous node is redirected to point to the node after the deleted element
The deleted element remains in memory but is no longer part of the active list
Extremely efficient compared to array deletion
Reshuffling (Randomization)
The actual song/data elements remain in their memory locations
Only the pointer connections are rearranged to create a different order
Allows random playback without physically moving data
Multiple reshuffles can create different orderings of the same elements
Nested Linked Lists (Linked List of Linked Lists)
Linked lists can be combined hierarchically to handle complex data structures with multiple levels of
relationships.

Practical Example - Academic Program Structure
Situation 1 (Fixed Structure): 8 semesters with 6 courses each → Use 2D array
Situation 2 (Variable Structure): Varying number of semesters and courses per semester due to
student circumstances, retakes, or deferrals → Use linked list of linked lists
Key Takeaways
Flexibility: Linked lists provide dynamic sizing through pointer-based connections
Memory Efficiency: Elements need not be stored contiguously; memory can be used anywhere
Directional Variants: Single, doubly, and circular linked lists address different navigation
requirements
Operation Efficiency: Insertion and deletion are simpler than in arrays as no shifting is required
Hierarchical Applications: Nested linked lists handle complex, multi-level data structures with
varying sizes
Practical Implementation: Modern programming languages provide built-in linked list
implementations; understanding the conceptual mechanics is essential for effective use
