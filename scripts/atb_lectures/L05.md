# Lecture 5: 5: Second Set of Algorithm Properties and Types of Algorithms

Lecture 5: Second Set of Algorithm Properties and
Types of Algorithms
Overview
This lecture covers the second set of desirable properties that algorithms should possess for effective
implementation, along with the main types of algorithms used to solve different problems.
Execution and Design Characteristics
Language Independence
A good algorithm should be expressed in logical steps that are generic and not tied to any specific
programming language
The algorithm's logic must be understandable regardless of the programming language used for
implementation
Example: A bonus calculation algorithm expressed in plain English is language-independent, while the
same logic written in Python-specific syntax is language-dependent
Language-independent algorithms can be translated into any programming language while maintaining
the same logic
Determinism
An algorithm is deterministic when the same input consistently produces the same output across
multiple executions
This property ensures predictability and reliability in algorithmic behavior
Example of Deterministic Algorithm:
Loan approval process: Fixed criteria (monthly income > 50,000 rupees AND credit score > 700) always
produces the same approval/rejection decision
The same set of inputs will always result in the same output
Example of Non-Deterministic Process:
Visa approval: Depends on visa officer's subjective judgment about trustworthiness, which can vary
between officers and interviews
Same application details may result in different outcomes depending on multiple factors beyond fixed
criteria
Algorithms must be deterministic to be reliably implementable in computing systems.
Feasibility
An algorithm must be implementable realistically within available resources such as system memory,
processing power, and time constraints.
Historical examples of feasibility challenges:
Cloud Computing: Technology existed in the 1990s but lacked feasibility due to slow internet speeds
and high costs; became popular in recent years with improved internet speeds and cheaper
infrastructure

Machine Learning/AI: Algorithms existed since the 1970s but became feasible only recently due to
cheaper computing power, increased data availability, and better memory capacity
Payroll Processing Example:
Feasible Approach: Read employee salary records one by one from the database, calculate net
salary, generate pay slip, repeat for next employee
Infeasible Approach: Load all employee records into memory simultaneously and process all at once,
which is very costly and impractical for regular computing systems
An algorithm must solve the problem within time and resource constraints; otherwise, organizations may
not invest in its implementation.
Generality
An algorithm should be general enough to handle all valid instances of a problem without special cases
The algorithm must work for all valid inputs, not just specific or unique cases
Example of Lack of Generality:
Assigning bonus only to employees named "Rahul" lacks generality and is specific to one case
This approach is unethical and not implementable in business
Valid vs. Invalid Inputs:
Invalid inputs (negative sales values, letters instead of numbers) may fall outside the algorithm's scope
Algorithms should handle all valid inputs consistently without special case conditions
A good algorithm applies universally to the problem domain, not to particular individuals or scenarios
Application of Properties: Review Questions
Question 1: Discount Algorithm Analysis
Algorithm: Randomly chooses a discount between 5% and 20% for all customers
Property Not Satisfied: Determinism
Reason: Random selection introduces uncertainty; the same purchase amount may result in different
discount percentages each time, violating the principle that same inputs should produce same outputs.
While randomness may be part of company policy, it goes against algorithmic principles.
Question 2: Customer Complaint Algorithm Analysis
Algorithm: Customer submits complaint → Determine customer's true intention → Provide solution
Property Not Satisfied: Feasibility
Reason: The second step (determining customer's true intention) is not strictly executable by a
computing system without extremely complex solutions (like AI with facial recognition), making it
impractical for a standard complaint handling system.
Types of Algorithms
1. Divide and Conquer Algorithm
Core Concept: Divide a large problem into smaller sub-problems, solve each independently, and combine
results to obtain the final solution
Everyday Analogy: Group projects where team members work on different sections and combine work at
the end

Business Example - Company Audit:
Large company divides audit work among regional offices (North, South, East, West, Northeast)
Each regional team audits their respective office accounts
All regional audit reports are combined into a single company-wide audit report
Smaller companies may use a single auditor who examines each office sequentially and combines
findings
2. Greedy Algorithm
Core Concept: Makes the best possible decision at the current point in time based on available
information and constraints
Key Characteristic: Assumes that taking the locally optimal choice will lead to a useful overall solution
Decision-Making Approach: Takes the best available option now, not necessarily the globally optimal
solution
Business Example - Making Change:
Customer pays 500 rupees for a 150 rupee ticket (change due: 350 rupees)
Cashier chooses one 200-rupee note, one 100-rupee note, and one 50-rupee note (greedy choice:
largest denominations first)
This is faster and more practical than counting 35 ten-rupee notes
Locally optimal choice produces a practical solution quickly
Investment Example: Investor with limited budget chooses stocks offering the highest immediate return,
potentially selling later when better opportunities emerge
3. Dynamic Programming Algorithm
Core Concept: Makes decisions for the future based on analysis of past data and current conditions
Key Characteristic: Uses historical data and patterns to inform future planning
Business Example - Inventory Reordering:
Reviews past three years of purchase history, holding costs, and demand patterns
Analyzes whether future demand will increase or decrease
Plans inventory accordingly for the next 12 months
Air Cooler Manufacturing Example: Order more inventory before March (summer season when demand
peaks) but reduce orders before rainy season (when cooler demand decreases and cold season
approaches with potential demand increase)
Core Principle: Look at past patterns and current inventory to plan optimal future purchasing decisions
Algorithm Type Matching Exercise
Situation 1: Production Planning
Scenario: Manufacturer decides monthly production by considering current inventory, previous production
levels, and expected future demand
Suitable Algorithm Type: Dynamic Programming
Reason: Uses past production data and inventory levels to predict and plan for future demand

Situation 2: National Sales Reporting
Scenario: National retail chain asks each regional office to prepare sales reports; head office combines all
regional reports into national report
Suitable Algorithm Type: Divide and Conquer
Reason: Breaks down national-level sales calculation into smaller regional problems, then combines
regional solutions
Situation 3: Investment Portfolio
Scenario: Investor with limited budget invests in opportunities offering the highest immediate return
before considering others
Suitable Algorithm Type: Greedy Algorithm
Reason: Focuses on locally best solutions at each point in time; may sell investments later if better
opportunities emerge, following immediate best returns

Key Takeaways
Execution properties (language independence, determinism, feasibility, generality) determine whether
an algorithm can be implemented and generalized
Algorithms must be deterministic to be reliably implementable
Feasibility depends on available technology, resources, and time
Generality requires handling all valid inputs without special-case logic
Three main algorithm types address different problem structures: division into subproblems, local
optimisation, and historical pattern analysis
