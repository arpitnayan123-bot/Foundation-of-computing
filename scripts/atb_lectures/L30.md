# Lecture 30: 30: Quick Sort: A Divide and Conquer Sorting Algorithm

Lecture 30: Quick Sort: A Divide and Conquer Sorting
Algorithm
Quick sort is an efficient divide and conquer sorting algorithm that addresses the limitations of elementary
sorting methods like bubble sort, selection sort, and insertion sort, which all have O(n²) complexity. Unlike
merge sort which divides the list into fixed halves, quick sort divides the list around a strategically chosen
pivot element, making it potentially more efficient with better average-case performance.
Core Concept of Quick Sort
How Quick Sort Works
Selects one element as a pivot
Compares all other elements with the pivot
Places smaller elements to the left of the pivot
Places larger elements to the right of the pivot
Recursively repeats the process on the left and right sub-lists
Continues until each part contains zero or one element
Key Difference from Merge Sort: Unlike merge sort's fixed division into halves, quick sort's efficiency
depends on the quality of pivot selection. With wisely chosen pivots, quick sort can be more efficient than
merge sort despite both having similar theoretical complexity.
Quick Sort Algorithm in Practice
Step-by-Step Process
Choose the last item as the pivot
Compare each item with the pivot
Move items smaller than pivot to the left
Move items larger than pivot to the right
Once pivot reaches its correct position, apply the same process to left sub-list
Apply the same process to right sub-list
Continue until all sub-lists contain single elements or are empty
Important Note: During partitioning, elements are not internally sorted—they are simply placed on the
left or right side of the pivot based on comparison.
Pivot Selection Strategies
Quick sort's efficiency heavily depends on pivot selection. Several approaches exist:
First Element: Simple but can result in O(n²) for already-sorted data
Last Element: Commonly used and demonstrated in examples, but may be suboptimal for sorted lists
Middle Element: Better than first or last in some cases, but not guaranteed to be effective
Random Element: Avoids worst-case patterns but lacks consistency

Median of Three Approach: Takes the first, middle, and last elements, sorts these three values, and
selects the middle value as pivot—typically provides better partitioning and is used in practical
implementations
Calculating Median of Three
Identify the first index (e.g., 0), last index (e.g., 6), and middle index (calculated as last index ÷ 2)
Extract the three values at these positions
Sort these three values
Use the middle value of the sorted trio as the pivot
Time and Space Complexity
Time Complexity
Average Case: O(n log n)
Best Case: O(n log n)
Worst Case: O(n²) — occurs when the pivot is the smallest or largest element, or when the list is
already sorted in opposite order
Space Complexity
Requires additional memory for recursive function calls
Generally requires less extra space than merge sort because elements are placed in their correct
positions during partitioning, eliminating the need for additional storage of intermediate results at
every level
Advantages of Quick Sort
Practical Efficiency: Despite similar theoretical complexity to merge sort, quick sort often performs
faster in practice due to better cache locality
Better Space Efficiency: Requires less additional memory compared to merge sort
In-place Sorting: Can be implemented to sort data within the original array structure
Scalability: Effective for large datasets, especially with good pivot selection strategies
Real-World Applications
E-Commerce Filtering
Price ranges can serve as pivots to filter products
Example: Setting $500 as a pivot to separate items below and above this price point
Multiple pivots can be applied sequentially to create price ranges (e.g., $200–$500, $500–$800)
General Use Cases
Sorting large datasets in databases
Organizing information in file systems
Processing performance-critical applications where space efficiency matters
Summary
Quick sort is a highly practical sorting algorithm that uses pivot-based partitioning to divide sorting
problems into smaller subproblems. Its average-case complexity of O(n log n) makes it significantly better
