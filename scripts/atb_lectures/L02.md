# Lecture 2: 2: Introduction to Pseudo Code Representation

Lecture 2: Introduction to Pseudo Code Representation
This lecture focuses on the use of pseudo code as a method to represent algorithms in a way that bridges
plain English and programming languages.
Overview
Pseudo code is a code-like representation of algorithms that is easily understandable by programmers and
developers without being tied to any specific programming language syntax. This approach allows
developers to convert pseudo code into any programming language (C, C++, Java, Python, etc.) and
enables people without programming experience to understand algorithmic logic through plain English.
Key Concepts and Definitions
Algorithm Components (Review)
Data: Actual values you work with
Variables: Constructs where data is stored during computation
Algorithms: Organized steps to convert data into desired outputs
Functions: Subgroups of organized steps within an algorithm
Pseudo Code vs. Code
Pseudo Code: Plain English written in a structured, code-like manner that programmers can
understand without language-specific syntax constraints
Code: Algorithm implemented using a specific programming language with its own syntax and
keyword requirements
The distinction is important because each programming language has unique syntax rules and
requirements that don't apply to pseudo code.
Data Types in Algorithm Design
When defining variables, you must specify the data type to indicate what kind of values the variable will
hold:
Integer: Stores whole numbers (e.g., 60, 65, 70)
Float: Stores decimal numbers (e.g., 62.5, 32.3)
Boolean: Stores only two values (0 or 1, yes or no)
Character: Stores text and letters (e.g., names, subject names)
Data Type Selection Example
Subject marks (whole numbers only) → Integer
Temperature measurements (can include decimals) → Float
Name of person → Character
Course completion status (yes/no) → Boolean

Practical Example: Calculating Average
Mathematical Approach
Sum all marks: 60 + 65 + 70 + 55 + 60 = 310
Divide by number of subjects: 310 ÷ 5 = 62 (average)
Algorithmic Approach (without simplification)
Define variables S1, S2, S3, S4, S5 as integer (for storing marks of each subject)
Input marks for each subject
Define variable "sum" as integer
Calculate sum = S1 + S2 + S3 + S4 + S5
Define variable "average" (AVG) as float
Calculate AVG = sum ÷ 5
Output the average
Simplified Algorithmic Approach (with variable consolidation)
Define S1 to S5 as integer; define sum as integer; define AVG as float
Input S1 to S5
Calculate sum = S1 + S2 + S3 + S4 + S5 (result: 310)
Calculate AVG = sum ÷ 5 (result: 62.0)
Output AVG
Introduction to Functions
A function is a reusable subgroup of organized steps that performs a common task. Functions can
significantly reduce algorithm complexity by condensing multiple steps into a single line.
Benefits of Functions
Simplifies algorithm representation
Reduces lines of code
Pre-built functions are available in programming language libraries
Commonly available functions include: sum, average, subtraction, etc.
Function Notation in Pseudo Code
Represented in flowcharts as rectangles with double vertical lines
Format: variable_name = function_name(input_parameters)
Example: AVG = average(S1, S2, S3, S4, S5)
The function receives input values, performs calculations, and returns (stores) the result in a variable
Example with Function
Define S1 to S5 as integer
Define AVG as float
Input S1 to S5
AVG = average(S1, S2, S3, S4, S5)
If AVG > 60, output "First Class"
End

Decision Structures in Pseudo Code
Conditional statements use the "if" keyword to check conditions and execute specific actions:
If AVG > 60: Output "First Class"
If AVG ≤ 60: Process ends (no output, or continue to next condition)
This structure allows algorithms to make decisions based on variable values.
Flowchart Representation
The complete algorithm can be represented as a flowchart:
Start
Define variables (S1-S5, AVG)
Input data (S1-S5) - shown as trapezoid
Call function to calculate average
Decision diamond: Is AVG > 60?
Yes: Output "First Class"
No: End
End
Key Takeaways
Multiple Representations: Algorithms can be represented as flowcharts or pseudo code
Language Independence: Pseudo code is not tied to any specific programming language, making it
universal
Data Type Importance: Pre-defining data types for variables is a best practice for understanding
operations and ensuring proper data storage
Functions as Tools: Functions are powerful tools for simplifying algorithms by encapsulating common,
reusable tasks
Flexibility in Learning: Pseudo code accommodates learners with varying programming experience—
those without coding background can understand through English, while experienced programmers can
quickly relate it to their preferred programming language
