# Lecture 4: 4: Properties of Algorithms in Real-World Business Contexts

Lecture 4: Properties of Algorithms in Real-World
Business Contexts
This lecture covers the essential properties that define a good algorithm, with emphasis on how these
properties apply to practical business situations. The course uses a business-focused approach rather than
a purely computational one to demonstrate how algorithms function in real-world settings.
Overview of Algorithm Properties
Algorithm characteristics are divided into two main categories:
Core Technical Characteristics
These properties focus on the fundamental nature of the algorithm itself, regardless of implementation
method (plain English, pseudocode, or flowchart):
Finiteness: Algorithm must terminate after a countable, finite number of steps
Definiteness: Each step must be clearly defined with no ambiguity
Well-Defined Inputs: External data requirements must be explicitly specified
Well-Defined Outputs: Algorithm must produce at least one clear expected result
Effectiveness: Algorithm must solve the problem efficiently and usefully
Execution and Design Characteristics
These properties determine whether an algorithm can be properly implemented and generalized:
Language Independence: Algorithm works regardless of programming language
Determinism: Same input produces same output consistently
Feasibility: Algorithm can actually be implemented
Generality: Algorithm applies broadly to similar problems
Detailed Property Analysis
1. Finiteness
Definition: An algorithm must end after a countable, finite number of steps without looping indefinitely.
Valid Example - Classroom Student Count:
Start with first student at first desk
Count each student exactly once
Move to next desk progressively
Stop at last student and display total
The algorithm terminates with a finite, countable number of steps (e.g., 40 or 600 students)
Invalid Example - Retail Store Customer Counter:
Check if customer has entered
If no, check again (return to step 1)
If yes, count and return to step 1

This creates an infinite loop because the system continuously checks for incoming customers with no

Solution: Add a reset condition (e.g., "reset counter to zero at midnight") to make the algorithm finite and
collect meaningful data within defined time periods.
2. Definiteness and Unambiguity
Definition: Each step must have exactly one clear interpretation with no room for multiple interpretations.
Valid Example - Calculate Average of Marks:
Input five marks (M1, M2, M3, M4, M5)
Calculate average: (M1 + M2 + M3 + M4 + M5) ÷ 5
Display average
Stop
Each step is precise and unambiguous with clear numerical operations.
Invalid Example - Ambiguous Tea-Making Algorithm:
Take some tea leaves
Add a little milk
Boil for a while
Add sugar if needed
Problems: "some," "little," and "a while" are subjective interpretations. Different people will produce
different results. First-time learners cannot follow this without outside knowledge.
Key Insight: Good recipes and algorithms specify exact measurements (e.g., "250 ml of milk" instead of
"a little milk"). Machines and computers cannot make subjective interpretations—they require precise,
quantified instructions.
Connection to Artificial General Intelligence: The challenge of creating AGI stems partly from this
property. While humans easily interpret ambiguous instructions like "come near me," machines require
explicit quantitative specifications. Current AI systems work well with specific, definite tasks but struggle
with ambiguous, general-purpose instructions.
3. Well-Defined Inputs
Definition: External data requirements must be explicitly and clearly specified.
Valid Example - Rectangle Area Calculation:
Input: Length (L) and Width (W)
Calculate: Area = L × W
Display area
Stop
Inputs are specific: exactly two values (length and width) are required.
Invalid Example - Vague Input Specification:
Input the required value
Calculate the area
Problems: "required value" is unclear; doesn't specify what values are needed. "Calculate the area"
doesn't indicate which formula or inputs to use. Both input specification and the step itself are ambiguous.

4. Well-Defined Outputs
Definition: Algorithm must produce at least one clear, expected result that matches problem
requirements, even when conditions are not met.
Valid Example - Loan Approval Process:
Input: Monthly income and credit score
Apply criteria: Income > 50,000 AND Credit score > 600
Output: "Loan Approved" OR "Loan Rejected"
The algorithm always provides a clear, definitive output. User knows the decision regardless of outcome.
Invalid Example - Undefined Output:
Input applicants' details (vague input)
Apply loan approval criteria
Display: "Processing Complete"
Problems: User doesn't know if application is approved or rejected. "Processing Complete" provides no
actionable information. Both input and output lack clarity.
Real-World Parallel: Good customer service (like email responses saying "We're working on it, will
respond in 48 hours") provides well-defined output even when the complete solution isn't ready. The
algorithm should always communicate a clear status or result.
5. Effectiveness
Definition: Algorithm must not only solve the problem but do so in a practical, useful manner considering
time, resources, and business objectives.
Valid Example - Inventory Reordering System:
Input: Current stock quantity
Define: Safety stock threshold = 50 units
Define: Purchase order quantity = 200 units
Logic: If stock < 50, create purchase order for 200 units; otherwise, maintain current stock
Effectiveness: Balances production continuity (doesn't risk running out) with cost management (doesn't
overstock). Avoids both production interruption and excessive storage costs.
Invalid Example - Ineffective Inventory Algorithm:
Check current stock
Order more items whenever stock looks low
Problems: "Low" is undefined and subjective; different managers interpret differently. "Order more items"
doesn't specify quantity; some order 200, others order 1,000. Results in inconsistent, costly decisions. May
cause either production risk or excessive inventory costs. Not effective for organizational goals.
Resource and Time Considerations:
An algorithm that solves a problem in 3 hours is ineffective for real-time loan approval
An algorithm requiring excessive computing resources is ineffective for devices with limited capabilities
Effectiveness encompasses not just correctness but practicality

Interconnection of Properties
All algorithm properties work together:
An algorithm with infinite loops violates finiteness and compromises effectiveness
Missing well-defined outputs often means well-defined inputs are also unclear
Violating definiteness makes it impossible to achieve well-defined outputs
Practical Exercise Examples
Example 1: Flawed Algorithm
Step 1: Input applicant details
Step 2: Evaluate eligibility
Step 3: Return to Step 2
Property Violated: Finiteness (creates infinite loop)
Secondary Issue: Well-defined output (never reaches conclusion)
Example 2: Ambiguous Discount Algorithm
Input: Customer purchase amount
If purchase amount is large, give large discount
Display final bill and stop
Property Violated: Definiteness (lacks precise definitions)
Problem: "Large" purchase and "large" discount are undefined
Impact: Different staff apply different criteria inconsistently
Summary of Key Takeaways
Core technical properties (finiteness, definiteness, inputs, outputs, effectiveness) define the algorithm
itself
Execution properties determine implementation feasibility and applicability
Business effectiveness requires balancing multiple properties simultaneously
Real-world algorithms must be both theoretically sound and practically useful
Ambiguity and vagueness are enemies of proper algorithms in computational contexts
