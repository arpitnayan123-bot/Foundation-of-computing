Tree Types
General Tree
Definition: A tree where the number of children per node is not fixed; each node can have zero, one,
two, or many children
Key Property: Each child has exactly one parent
Real-World Applications:
Folder structures (directories and subdirectories in file systems)
Family trees
Organization hierarchies (executives, managers, employees)
Biological taxonomy (kingdom, phylum, class, order, etc.)
Binary Tree
Definition: A tree where each node has at most two children (left and right child)
Key Property: The number of children can be 0, 1, or 2
Applications:
Tournament structures (tennis, badminton—individual sports with knockout rounds)
Decision trees and flowcharts (yes/no branching)
Expression evaluation
Complete Binary Tree
Definition: A binary tree where all levels are completely filled except possibly the last level, which is
filled from left to right
Constraint: All nodes except possibly the last level have exactly two children
Characteristic: If a node exists on the last level, all positions to its left must be filled
Binary Search Tree (BST)
Definition: A binary tree with an additional property where left child value < parent value and right
child value ≥ parent value

Key Characteristics:
Enables efficient searching similar to searching in a physical dictionary
If values are inserted in sorted order, the tree can become skewed (like a linked list), reducing

AVL Tree
Purpose: Solves the skewness problem of Binary Search Trees
Key Property: Maintains balance by ensuring the height difference between left and right subtrees is
at most 1
Mechanism: Uses rotations to rebalance the tree when height difference exceeds one level
Benefit: Guarantees efficient search regardless of insertion order
Applications: Operating system memory indexing, library catalog systems
Heap
Definition: A specialized binary tree where the parent-child relationship follows a specific ordering
Types:
Max Heap: Parent node value is always greater than child node values (root contains maximum)
Min Heap: Parent node value is always less than child node values (root contains minimum)
Note: No left-right ordering requirement, only parent-child relationship matters
Application: Priority queues (higher priority items processed first; implementation depends on
whether priority 1 is highest or priority 10 is highest)
Hashing
Basic Concept
Hash Function: Takes an input of any size and produces a fixed-length output
Key Property: The output length remains constant regardless of input size
Simple Example: Using modulo (mod) operator to find remainder when dividing by a number
Modulo Function
Definition: A basic hash function that divides input by a number and returns the remainder
Example:
101 mod 10 = 1 (last digit)
27 mod 5 = 2 (27 ÷ 5 = 5 remainder 2)
Possible Values: For mod n, possible outputs are 0 to (n-1)
Use Case: Distributing data into buckets; helps organize large datasets
Hash Table (Key-Value Pairs)
Structure: Stores data as key-value pairs with indexed buckets
Process:
Calculate hash of input
Use hash value to determine bucket location
Store or retrieve data from that bucket
Advantage: Enables faster searching through indexing rather than sequential search
Application: Database indexing for efficient data retrieval on billions of records

Hash Collision
Definition: Occurs when two different inputs produce the same hash output
Example: Numbers ending in 2 (12, 22, 32) all have hash value 2 using mod 10
Solution - Chaining: Link items with the same hash value using linked lists, pointing subsequent
items to the previous item at that index
Trade-off: Chaining increases search time slightly but keeps most data in correct bucket
Cryptographic Hash Properties
Deterministic: Same input always produces same output
Fixed Length: Output length is constant regardless of input size
One-Way Function: Cannot reverse the process to obtain original input from hash (critical for
security)
Avalanche Effect: Single character change in input produces completely different hash output
Collision Resistance: Extremely difficult (practically impossible) to find two different inputs with same
hash
Applications of Hashing
Password Storage: Databases store password hashes rather than actual passwords; when user logs
in, entered password is hashed and compared to stored hash
Integrity Checks: Calculate hash of original data/file, transmit both separately; recipient recalculates
hash and compares to verify no tampering occurred
Indexing: Database systems use hash functions to create indexes for quick data retrieval
Blockchain
Core Concept
Definition: A data structure consisting of blocks linked in a chain, where each block contains the hash
of the previous block
Key Characteristic: A block stores its own transaction data, its own hash, and the previous block's
hash
Block Structure
Contents:
Set of transactions (banking records, health reports, university records, etc.)
Hash of current block (calculated from current transactions)
Hash of previous block (creates the chain link)
Genesis Block: First block has no previous block; its previous hash field is null or zero
Why Blockchain is Secure
Immutability through Hashing:
If any transaction in a block is changed, that block's hash changes completely
This causes mismatch with the next block's "previous hash" reference
The mismatch propagates through all subsequent blocks, making tampering obvious
Decentralization:
Blockchain stores copies of all blocks across multiple nodes in a network
All nodes maintain identical copies of the complete ledger

Single node tampering is detected by comparing with other nodes
Consensus Mechanism:
Network nodes must agree before accepting new blocks
Makes simultaneous hacking of 51% of nodes impractical (theoretically possible but resource-intensive)
Merkle Tree
Definition: A tree structure using hashing for integrity verification of multiple transactions within a
block
Process:
Hash each individual transaction (T1, T2, T3, T4, etc.)
Pair hashes and hash their combination (creating intermediate nodes)
Continue combining and hashing until reaching single root hash
Purpose: Creates layered security; any transaction change alters the root hash, signaling tampering
Advantage: Provides transaction-level integrity verification
Types of Blockchain
Public Blockchain:
Anyone with processing power can join the network
Most popular example: Bitcoin
Uses Proof of Work: nodes solve complex computational problems (mining) to validate blocks
Mining difficulty increases over time as more nodes join
Highly resource-intensive but completely decentralized
Enterprise Blockchain:
Private blockchains used by organizations across multiple locations
Fewer nodes than public blockchains
More cost-effective for specific organizational needs
IBM has offered enterprise blockchain solutions
Generally not adopted widely due to costs
Applications of Blockchain
Cryptocurrency:
Bitcoin is the most well-known application
All transactions are recorded permanently with complete traceability
New blocks continuously added; no deletion allowed
Tamper-proof due to hash linking and decentralization
Smart Contracts:
Blockchain-based agreements that execute automatically
More secure than paper-based contracts as changes are recorded permanently
Contract terms cannot be altered without detection
Record Management:
Government records (revenue reports, property records)
Health records

Blockchain vs. Linked List
Linked List: Uses memory addresses to point to next node; data typically stored on single system
Blockchain: Uses hash values to link blocks; data stored across multiple nodes (decentralized)
Both chain data but differ fundamentally in linking mechanism and distribution
Security Consideration
51% Attack: Theoretically possible if attacker controls 51% of network nodes simultaneously, but
practically infeasible due to resource requirements and simultaneous coordination needed
Current Limitation: High storage requirements as all data is replicated across nodes, making
blockchain expensive for implementation
