Algorithm Complexity and Time Analysis
Big O Notation is used to measure how algorithms scale with input size. Rather than calculating exact
execution time, it analyzes the growth rate of processing time as input size increases.
Common Complexity Types (from fastest to slowest)
O(1) — Constant time: Fixed number of operations regardless of input size (rare in practice)
O(log n) — Logarithmic: Growth rate is relatively slow, ideal for practical applications
O(n) — Linear: Operations increase proportionally with input size, manageable
O(n log n) — Operations grow slightly faster than linear but still acceptable
O(n²) — Quadratic: Rapid growth, impractical for large datasets
O(2ⁿ) — Exponential: Extremely rapid growth, should be avoided

Linear Search Algorithm
Starts at first index and compares each element sequentially
Complexity: O(n)
Works on unsorted data
Simple but inefficient for large datasets
Binary Search Algorithm
Starts at middle index and divides search space in half based on comparison
Complexity: O(log n)
Requirement: Data must be sorted
Much more efficient than linear search for large datasets
Example: Searching 10 million records requires approximately 24 comparisons
Jump Search Algorithm
Makes fixed-size jumps through data (jump size = √n)
When target is exceeded, moves back one block and performs linear search
Complexity: O(√n)
Less common but useful for scenarios where binary search isn't applicable
Example: Finding a timestamp in a video by jumping in fixed intervals
Exponential Search Algorithm
Jump size doubles with each step (1, 2, 4, 8, 16...)
When target is exceeded, performs binary search on the final range
Complexity: O(log n)
Efficient when target location is unknown or data structure grows dynamically
Better than jump search for certain scenarios
Hash Search Algorithm
Uses hash function to calculate index position (e.g., modulo operation)
Average case complexity: O(1)
Worst case complexity: O(n) — When multiple elements hash to same index (collision)

Graph Traversal Methods
Depth-First Search (DFS):
Follows one path to its end before backtracking
Uses stack-based approach
Complexity: O(V + E) where V = vertices, E = edges
Breadth-First Search (BFS):
Explores level by level from source node
Uses queue-based approach
Complexity: O(V + E)
Dijkstra's Algorithm (Shortest Path)
Used to find shortest path between nodes in a weighted graph.
Key Requirements:
Graph must be weighted (each edge has a cost/weight)
Weights must be non-negative
Works on directed and undirected graphs
Algorithm Process:
Set source node distance to 0, all others to infinity
Select unvisited node with smallest known distance
Update distances to neighboring nodes if shorter path found
Mark node as visited
Repeat until destination reached or all nodes visited
Example: Finding route from Home (A) to University (B):
Direct path A→B might be 4 km
Alternate path A→C→B might be 3 km (2 km + 1 km)
Algorithm identifies the 3 km route as shortest
Complexity: O(V²) for basic implementation
Related Graph Algorithms
A* Algorithm: Combines actual cost with estimated distance, used in GPS navigation
Floyd-Warshall: Finds shortest paths between all pairs of nodes
Prim's/Kruskal's Algorithm: Finds minimum spanning tree for network connectivity
